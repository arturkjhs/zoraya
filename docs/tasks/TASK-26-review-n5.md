1. **warning: a short, all-zero or empty seed is not refused, so the output can be predicted.** user/src/bin/rngd.rs:154-163 (`Generator::new(&seed)` on any length, empty included), crates/zoraya-rng/src/lib.rs `Generator::new` (tests.rs:46 checks that an empty seed still gives output), crates/zoraya-tls/src/lib.rs:75-77 (`seed_random` says "32 bytes or more" but does not check it). A missing seed does fail closed (init.rs `start_rng`: no rngd, then fetch says "the system gave no random bytes"). But a boot loader that passes 1 to 31 bytes, or 32 zero bytes, gives a generator whose stream is known, and the ECDHE keys of every handshake are known with it. Fix: rngd refuses to serve when the seed is under 32 bytes or all zero, and reports it as "no entropy source". `seed_random` returns `Result` and refuses fewer than 32 bytes. Add a test of each.
2. **warning: with no RTC reading, the clock is the volume's latest time, and TLS uses it.** user/src/bin/init.rs:370 only prints a line when `read_rtc() == 0`. fsd then takes `latest + 1` as the base, and fetch.rs `wall_clock` accepts it. The date can be weeks or months old (driver 1 of ADR-0226 says that is not acceptable), so a certificate that expired in that time passes. Fix: carry where the date came from (for example a flag next to `realtime_base` in ZNS1, or TimeBase replying "no floor"), and make `wall_clock` give `None`, which is NoClock, when no RTC floor was applied. Test: a record with the flag off makes `connect` fail with NoClock.
3. **warning: any program can use up the random service's 256 connections.** rngd.rs:123-139, zoraya-rng `Service::handle` SHARE. Every native program gets a connection, and any connection may `Share` without limit. A program that sends 256 `Share` messages and keeps its ends fills the table. After that zosh.rs:1081 `share` fails silently, so every new program (fetch included) gets no randomness, and a restarted shell gets none either. Fix: a budget of shares per connection (one level: only init's and the shell's connections may share, which a program's own `fork` share does not need), or count shares against the connection that made them and free them when it closes. Add a host test in `share_is_bounded_and_closes_on_nonsense`.
4. **warning: nothing in `make check` covers vendor/.** Makefile:768 leaves vendor/ out of check-host-paths, and INV-0289-2 (vendor equals upstream) is not in `make check`. A later edit to ring's C or assembly, which runs in every TLS program, would pass every check without being seen. Fix: commit a SHA-256 manifest of vendor/ring and check it in `make check` (no network needed). Make the host-paths exclusion `vendor/ring/` only.
5. **note: the kernel keeps the seed after handing it on.** kernel/src/device.rs:65 and 137: `seed_object()` clones the Arc, so the object and its frame stay alive after rngd has closed its handle. ADR-0288 item 4 says only the copy in the DTB remains. Fix: `SEED.lock().take()`, and correct the ADR text. rngd also drops its seed `Vec` without wiping it.

Makefile:325 only greps for "request of", so N > 0 on the expired or wrong server would pass. Fix: also require `^tls (expired|wrong): ended after 0 request bytes`.
