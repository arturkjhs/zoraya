# TASK-02b: what parallel builds add to the POSIX surface

This summarises M5: libc functions, syscalls and argument patterns under `make -j`, a shared jobserver, shell-level
parallelism and interrupted builds. Each is compared with the serial TASK-02 runs.

Sources:

- `tools/posix-surface/results/par/parallel-tables.md` (generated by `analysis/parallel.py`);
- [`syscall-delta.csv`](syscall-delta.csv) (`syscall, workload, serial_count, parallel_count, notable_args`);
- `results/par/syscall-reps.tsv`, for the per-run counts behind the means.

How the data was produced is in [`research-log.md`](research-log.md) and [`../task-02/method.md`](../task-02/method.md).

## Setup in one paragraph

- **Workloads.** W2-j (Lua) and W3-j (SQLite as a 3-rule Makefile) at `-j2` and `-j4`. The VM has 4 cores, so `-jN`
  is `-j4`. GNU make 4.4.1 ran with `--jobserver-style=pipe` and `--jobserver-style=fifo`. pdpmake ran with `-j`,
  which it accepts but does not implement.
- **W8.** A synthetic recursive build: top → `a`, `b` → four leaves. Each leaf has 8 independent table-generator
  targets, 8 objects and an archive. Serially it takes about 13 s; at `-j4` about 3.5 s.
- **W9.** W8 at `-j4`, interrupted from an interactive dash on a pty. Two cases: Ctrl-C, and SIGTERM to the top make
  only. Delays of 0.3, 1.5 and 3.0 s, 3 repetitions each.
- **W10.** A dash script with `cmd &`, `wait` and concurrent pipelines, plus a serial variant.
- **Modes and repetitions.**
  - Everything ran twice: once with the interposer (`dynamic`) and once under `strace -f`.
  - The non-interrupt workloads were repeated twice in each mode.
  - All 220 runs exited as expected: builds 0, Ctrl-C 130, SIGTERM 143. Every build's output check passed.

## Concurrency actually achieved

| Build | Max recipes at once | Duration under strace (s) |
|---|---|---|
| W8 GNU make `-j1` / `-j2` / `-j4` (both styles) | 1 / 2 / 4 | 13.4 / 6.8 / 3.4–3.5 |
| W8 pdpmake `-j1` / `-j2` / `-j4` | 1 / 1 / 1 | 13.3 / 13.3 / 13.3 |
| W2 GNU make `-j2` / `-j4` | 2 / 4 | 0.5 / 0.3 |
| W2 pdpmake `-j2` / `-j4` | 1 / 1 | 0.8 / 0.8 |
| W3 GNU make `-j2` / `-j4` | 2 / 2 (only two compiles exist) | 0.2 |

pdpmake is serial at any `-j`. Everything below about parallel behaviour is therefore GNU make; pdpmake's rows in
`syscall-delta.csv` are identical to its serial runs.

## New libc functions (interposer, lower bound)

Functions called in TASK-02b runs that the same program never called in TASK-02:

| Program | New for this program | Of those, new to the TASK-02 lower bound altogether |
|---|---|---|
| GNU make | getpid, kill, mkfifo, open, pselect, signal, sscanf, strsignal, ttyname, waitpid, write | kill, mkfifo, pselect, ttyname |
| dash | signal, stpncpy, strsignal | stpncpy |
| pdpmake | chdir | — |
| toybox | writev | writev |

Six functions are new to the TASK-02 lower bound overall: `kill`, `mkfifo`, `pselect`, `stpncpy`, `ttyname`,
`writev`. All were already in the programs' static imports (TASK-02 upper bound). Parallelism exercises code that
was already linked; it does not widen the import surface.

- **The jobserver:** `mkfifo`, `open`, `write`, `pselect`, `waitpid` (non-blocking reaping) and `sscanf` (parsing
  `--jobserver-auth`).
- **The interrupt cascade:** `kill`, `signal`, `strsignal` (the "Interrupt"/"Terminated" messages) and `getpid`
  (re-raise to self).

## New syscalls and argument patterns

Syscalls absent from the serial run and present under `-j` (means over repetitions; `syscall-delta.csv`):

| Workload | New syscalls |
|---|---|
| W2 GNU make `-j4` fifo | `pselect6` 55.5, `rt_sigreturn` 20.5, `write` 38, `dup3` 27, `mknodat` 1 |
| W2 GNU make `-j4` pipe | `pselect6` 56.5, `rt_sigreturn` 21.5, `write` 38, `dup3` 27 |
| W8 GNU make `-j2` fifo / pipe | `pselect6` 67, `rt_sigreturn` 66, `write` 2 (+ `mknodat` 1 for fifo) |
| W8 GNU make `-j4` fifo / pipe | `pselect6` 78.5 / 89, `rt_sigreturn` 56 / 60, `write` 21 / 22 (+ `mknodat` 1 for fifo) |
| W3 GNU make `-j4` | `pselect6` 1, `write` 4, `dup3` 1 (+ `mknodat`, `getpid` for fifo) |
| W10 dash parallel vs serial | `rt_sigsuspend` 2 |
| W9 vs a complete W8 `-j4` | `kill` 7 (Ctrl-C) / 17 (SIGTERM), `tkill` 1 (Ctrl-C only), `setpgid` 4, `getpgid` 1, `readlinkat` 2 |

No `epoll_*`, `ppoll`, `poll` or `select` appeared in any run. No `waitid` either. No new syscall appeared for
pdpmake.

**Argument patterns that define semantics** (`notable_args` in `syscall-delta.csv`; its counts are *sums* over the
repetitions, while `serial_count` and `parallel_count` are means):

- **`pselect6`.** Always `pselect6(4, [3], NULL, NULL, NULL, {sigmask=[]})`: one fd (the jobserver read side), no
  timeout, and an empty signal mask. SIGCHLD, blocked everywhere else, is unblocked only inside this call.
  - In W8 `-j4` most calls end interrupted by SIGCHLD (`ERESTARTNOHAND`) rather than with a token: 55–60 of 72–100
    calls per build.
  - In W2 `-j4`, 20–22 of 55–57.
  - Every interruption is followed by `rt_sigreturn` returning `EINTR`, which is how the handler's return surfaces.
- **`wait4`.** It grows from 40 to about 135 (W2) and from 78 to about 226 (W8): GNU make polls `wait4(-1, WNOHANG)`
  after every wake-up. Blocking `wait4(-1, 0)` remains for the final reaps.
- **Jobserver.**
  - FIFO style: `mknodat("/tmp/GMfifo<pid>", S_IFIFO|0600)`, then `openat` read side `O_RDONLY|O_NONBLOCK`, write
    side `O_WRONLY`. Only the top make opens the read side with `O_NONBLOCK`; the 6 sub-makes open it `O_RDONLY`
    and set `O_NONBLOCK` afterwards with `fcntl(F_SETFL)`. The auth string `fifo:/tmp/GMfifoN` goes to every process.
  - Pipe style: `pipe2` with flags 0, and `--jobserver-auth=3,4` for recursive makes. Every other recipe gets
    `3,4` followed by `--jobserver-auth=-2,-2`, which tells a sub-make that the fds are not real.
  - Tokens are single `+` bytes written to and read from those fds:

    | Build | Token reads per build | Comment |
    |---|---|---|
    | W2 `-j2` / `-j4` | 34–36 / 38 | each compile beyond the first needs one |
    | W8 `-j2` | 2 | every make runs its first job on the implicit slot it was started with; the single token starts the second level-1 make, after which only two leaf makes run at a time |
    | W8 `-j4` | 17–26 | varies run to run |
    | W3 `-j2` / `-j4` | 2 / 4 | |

  - Token reads after a ready `pselect6` sometimes fail with `EAGAIN` (another make took the token first): 9 in two
    W8 `-j4` fifo runs.
  - `fcntl(F_SETFL, O_NONBLOCK)` and `F_GETFL` make the read side non-blocking. Close-on-exec toggling
    (`F_SETFD`/`F_GETFD`) around recursive spawns accounts for the extra `fcntl` calls in pipe style (W8 `-j4`:
    256 → 344 pipe vs 283 fifo).
- **Stdin of parallel jobs.** Each job spawned while another runs gets a "bad stdin": a pipe whose write end is
  closed. That shows as at most one extra `pipe2` per make, and only in makes that run jobs concurrently (W2 +1 for
  3 makes, W8 `-j4` +5.5 for 7), plus `dup3(5, 0, 0)` in the spawned child (`get_bad_stdin`, a
  TASK-02 M3 site).
- **Signal handling.** `rt_sigaction` and `rt_sigprocmask` counts are *unchanged* between serial and parallel GNU
  make runs (W8: 1698 and 592 in both). The handlers and masks are set up identically at every `-j`. What changes is
  that SIGCHLD is now delivered while make waits: `rt_sigreturn` from 0 to 20–66.
- **Inherited file descriptors.**
  - Pipe style: fds 3 and 4 are inherited by recursive makes only. Close-on-exec is cleared just for those spawns
    (`jobserver_pre_child`).
  - Fifo style: nothing is inherited. Each sub-make opens the path from `MAKEFLAGS`.

## Signals actually delivered

| Workload family | Delivered (strace, totals over repetitions) |
|---|---|
| GNU make `-j` builds (W2, W3, W8) | SIGCHLD only, `CLD_EXITED`, to the make that started the child |
| pdpmake `-j` builds | SIGCHLD only, as serial |
| W10 dash parallel | SIGCHLD to the shell (incl. one `CLD_KILLED` from `yes`); SIGPIPE to `yes` when `head` exits |
| W9 Ctrl-C | SIGINT from the tty (`SI_KERNEL`) to every process of the foreground job. Each make then sends SIGINT to itself after cleanup (`SI_USER`); the shell sends SIGINT to itself (`SI_TKILL`). SIGCHLD `CLD_KILLED` up the tree |
| W9 SIGTERM | SIGTERM from the harness to the top make only. Each make forwards SIGTERM to its children, then to itself after cleanup. SIGCHLD `CLD_KILLED` up the tree |

The SIGPIPE to `yes` shows `si_code=SI_USER` from `yes` itself. That is how Linux reports the kernel-generated
SIGPIPE on a write to a closed pipe; `yes` calls no `kill`.

## Interrupted system calls

| Workload family | `EINTR` / `ERESTART*` |
|---|---|
| GNU make `-j` builds | `pselect6` `ERESTARTNOHAND` (SIGCHLD), followed by `rt_sigreturn` `EINTR`, in the make that waits |
| W10 | `rt_sigsuspend` `ERESTARTNOHAND` in the shell's `wait` |
| W9 (both cases) | as above, plus `wait4` `ERESTARTSYS` in the top and level-1 makes. They were blocked reaping when the signal arrived; the call is abandoned, because the handler issues its own `wait4` calls and never returns. SIGTERM: in 4 of 9 runs a leaf make's `writev` inside the handler is interrupted by a nested SIGCHLD and restarted (`SA_RESTART`) |

No `EINTR` reached program code as an error return, except where the program asked for it: `pselect6` with its
atomic mask, and `sigsuspend`.

## Interruption: what happens to the build (W9)

The event sequences are in [`event-timelines.md`](event-timelines.md). Outcomes per run are in
`parallel-tables.md` → "W9 outcomes".

| | Ctrl-C | SIGTERM to top make |
|---|---|---|
| make exit status (as seen by the shell) | 130 (killed by SIGINT) | 143 (killed by SIGTERM) |
| who gets the signal | every process in the foreground process group, at once, from the tty driver | the top make; it forwards SIGTERM to its children, and they to theirs |
| partial targets | each leaf make deletes the target its running recipe was writing (`unlinkat(tN.h)`, "Deleting file"); 4 per run | 4 per run, except one strace run with 3 (a leaf make started a new recipe before the forwarded SIGTERM arrived and killed it before it created its target) |
| partial targets left behind | none, in all 36 runs | none |
| processes left 0.5 s after make returned | none | none |
| children terminated by | SIGINT from the tty (not by make) | SIGTERM sent by their parent make |
| make's own exit | re-raises the signal after cleanup (`kill(getpid(), sig)`) | the same |
| shell afterwards | takes the terminal back (`TIOCSPGRP`), then interrupts itself (`tkill(SIGINT)`) and abandons the rest of the command line | takes the terminal back; no self-interrupt |

Interrupting at 0.3, 1.5 or 3.0 s changed only how far the build had got: 0, 12 and 24–28 of 32 tables complete.
The sequence of event kinds did not change (`event-timelines.md` → stability tables).

## What this adds to the TASK-02 picture

1. **Parallel make adds a readiness wait.** It is exactly one: `pselect6` on one fd with a signal mask. It is the
   first readiness call in any TASK-02/02b core workload; TASK-02 serial builds made none. It also adds the
   jobserver: one FIFO or pipe, one-byte tokens, and fd numbers or a path published in `MAKEFLAGS`.
2. **The same signal dispositions, now on the hot path.** Serial and parallel GNU make install the same handlers and
   masks. Under `-j`, SIGCHLD becomes the main wake-up of every waiting make.
3. **No new import surface.** All six newly observed libc functions were already in the TASK-02 static upper bound.
4. **Shell-level parallelism adds `sigsuspend`-based waiting and inherited ignores.** Background jobs ignore SIGINT
   and SIGQUIT. The shell sleeps in `rt_sigsuspend` until SIGCHLD arrives.
5. **Interruption adds `kill`, `tkill` (the shell's self-interrupt) and target deletion.** The extra `setpgid`,
   `getpgid`, `readlinkat`, `TIOCSPGRP` and `ttyname` in W9 come from running make under an interactive shell on a
   pty, not from the interruption. The kinds of events were the same in every repetition. What varied with timing
   is described in `event-timelines.md` → stability.
