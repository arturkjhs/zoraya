| Id | Where | Finding | Severity (error / warning / note) | Suggested fix |
|---|---|---|---|---|
| S1 | ADR-0153, table "Designated operands", kinds `create`, `remove`, `rename` | A `create` operand adds "the parent directory of the named path" with `read, write, create, sync, clone`. Under ADR-0055 a directory connection reaches its whole subtree (ADR-0013 rule 6, `open` with a multi-component `RelativePath`), so `cp notes.txt notes.bak` in `~` hands `cp` write and create over every file below `~`. That is almost `+w ~` (it lacks only `remove` and `rename`). In the same way, `rm old.txt` gets `remove` over the whole tree below the parent. Neither the ADR nor `grants` says this: tour example 14 prints `~/project   create (operand TO: notes.txt)`, which reads as "may create notes.txt". The least-authority claim (driver 1, "exactly what the line shows") does not hold for the commonest commands. | error | Give the program one name, not the directory. Options: the shell makes the entry itself (an unnamed create plus publish, ADR-0010, handed over as a file connection); or ADR-0055 gains a connection narrowed to one name in a directory; or the shell opens the existing target for `write` and `remove`. Failing that, state the real reach in the table and in `grants` ("create and change anything in ~/project") and record it as a known limitation. |
| S2 | ADR-0153, `cwd: write`; ADR-0158 example and the note under it | `cwd: write` gives the current directory entry the `tree` rights. In ADR-0158's example `make -C big &` is run in `~`, so `make` gets `+w ~` (all of home), as well as `~/big` from the `tree` operand `-C`. The `jobs` line shows only `(+w ~/big)`, and the note under the example explains only the `-C` entry. A description can therefore turn any command run in `~` or `/` into a whole-tree grant, and the display understates it. | error | Show the cwd entry in `jobs` and `grants` (`+w ~ (cwd)`). Decide whether `cwd: write` should yield to a `-C`/tree operand when there is one. Consider making `cwd: write` need a visible confirmation, or a literal `+w .`, rather than a description key. |
| S3 | ADR-0153, driver 3 and INV-0153-3 vs "designation is authorization" | Driver 3 says "no value, file or program output can widen what a command receives". But designated operands come from values: `rm $(cat list.txt)`, `for f in $(cat paths) { cat $f }` and `cp $x /config/settings` grant whatever the data names, with whatever right the operand kind gives, including `..` paths resolved against the shell's own (whole-volume) table. INV-0153-3 covers only `+r`/`+w` tokens, so it does not test the driver as it is worded. This tension is not stated. | error | Reword driver 3 to "no data can create a grant token". State plainly that operands taken from expansions designate, and therefore authorize. Decide whether operands that come from `$(...)` or variables should be confined to the current directory or to entries the line already names, or should be shown by `grants`. Add an open question. |
| S4 | ADR-0153, "Explicit grants", `+w $out` | `PATH` "may contain" a variable, but ADR-0150 rule 3 gives no argument for an empty list and several arguments for a list. So `+w $out rm x` with an empty `$out` parses as grant `rm` for command `x`, and with `$out = (a b)` it parses as grant `a` for command `b`. The value decides which word is the command and which path is granted, which is data shaping a grant. Globs after `+r` (`+r ~/src/*`) are also undefined. | error | Require the word after `+r`/`+w` to expand to exactly one argument (an empty list or several is an error before anything runs). Forbid globs there, or define them. Add this to INV-0153-3's test values. |
| S5 | ADR-0153, designated operands and link objects (ADR-0013 rule 7, ADR-0107 item 7) | The ADR does not say what the shell does when a designated path is or passes through a link object. If the shell follows links when it resolves designations, `cat notes` in a directory where `notes` is a link to `/config/settings` grants a file the person never named, and the target can be anywhere the shell holds (its table is the whole volume). If it does not follow them, a native program receives the link and gets `IsLink`. The ADR is silent, and so are INV-0153-2's tests. | error | Decide this. Recommended: the shell resolves link objects with ADR-0107 item 7's rules, but only within entries the line already grants (the cwd entry, `+r`/`+w`), and refuses a designation whose link target leaves them, with a message. Add link cases to INV-0153-2. |
| S6 | ADR-0153 item 4, tour example 16, ADR-0153 example `+r ~/common tcc main.c` | Example 16 depends on `tcc` in `~/project` opening `../include/greet.h` through the `~/include` entry. In `zosh`'s table, cwd is an entry of its own (`~/project`, path ""). ADR-0107 item 6 resolves a relative path "against cwd's entry and path", with `..` "dropped at the root" (INV-0002-4: "`..` at an entry's root resolves to the entry's root"). Read that way, `../include/greet.h` becomes `~/project/include/greet.h` and the `+r` grant does not help. The ADR's own words ("`..` clamped at an entry's root") give that reading too. The tour's central grant example works only if relative paths are first made absolute from the cwd's canonical path. ADR-0107 does that only when cwd's entry is `/`. | error | State the resolution rule that `zosh` tables need: cwd recorded as its absolute canonical path, and relative paths made absolute before longest-prefix matching. If ADR-0107 item 6 or INV-0002-4 does not already mean this, declare a tension with it. Add the example as a resolver test. |
| S7 | ADR-0153 "POSIX programs", ADR-0156 item 2 | Descriptions are authority (operand kinds, `cwd: write`), yet a POSIX program's description is an ordinary file `/zoraya/commands/NAME.cmd`, and it is looked up by command name. (1) Anything granted `+w /`, or run with `cwd: write` in `/` (for example `make` there), can write `/zoraya/commands/cat.cmd` or `tcc.cmd` and give later runs `cwd: write` or `tree` operands: a grant obtained from file content. (2) A user-built `./tcc` or `./make`, which has no note and is therefore "POSIX", picks up the trusted description by name. ADR-0156's vision paragraph admits only "a program from an untrusted source would need its description checked". | error | Key external descriptions to the program file, not the name: for example only for programs under `/bin` and `/usr/bin` that the description lists by path. Keep `/zoraya/commands` out of reach of `cwd: write` and `tree` grants, or read it from the ramdisk or a read-only connection that `init` gives. Never apply a description by name to a path containing `/`. Add an invariant. |
| S8 | ADR-0153 "POSIX programs": "A program file whose image has no Zoraya description note ... is a POSIX program" | A native program without a description note (`echo-args`, every test program, a user-built native program) would be run through the broker with a `libposix` bootstrap record that it does not read, and it would get no `in/out/err` or record in the native layout. The test is about authority data, not about the program's ABI. | warning | Classify by a separate marker: an ELF note written by the native runtime's linker script, or by `zcc`'s `crt1`. A native program without a description then runs with no designated operands. |
| S9 | ADR-0153 item 2 and ADR-0158 rule 1 vs ADR-0104 items 1 and 4 | "Every command receives ... its own job, a sub-job of the shell's", and "a job ... run in a new sub-job of the shell's job holding every element". But `spawn_prepare` creates a POSIX process's job inside the broker's session job (ADR-0104 item 1: session job, then group job, then process job), not in `zosh`'s tree. A pipeline that mixes native and POSIX elements is therefore split across two trees. `job_signal`, `job_kill` and `job_suspend` on `zosh`'s sub-job miss the POSIX elements; "no `disown`: a job lives in the shell's job tree" is false for them; INV-0158-1 and INV-0153-1 cannot hold for POSIX commands. Undeclared tension with ADR-0104. | error | Either have the broker accept a caller-provided parent job (`spawn_prepare` with a group job from `zosh`'s tree, a change to ADR-0104 to be declared), or state that POSIX jobs live in the broker's tree and that every job operation on them goes through the broker (`kill(-pgid)`), and adjust ADR-0153 item 2, ADR-0158 rules 1 and 5 and their invariants. |
| S10 | ADR-0153 "POSIX programs", `zosh` as broker client | `zosh` "holds a broker connection as a native parent ... calls `spawn_prepare` and `spawn_commit` as `libposix` would". In ADR-0104 the broker creates one connection per POSIX process, `spawn_prepare`'s `Inherit` uses the caller's group, and `reap(pid)` is "allowed to the parent only". `zosh` has no pid, no group and no such connection. How it gets the connection, which group `Inherit` means for it, and who reaps (pids are never reused, ADR-0104 item 2) are all unstated. The declared tension covers only item 12 (no `/bin/sh` first process). | warning | Add these to the ADR-0104 tension: a native-client connection that `init` gives `zosh`; `New` group for every job; `zosh` calls `reap`. |
| S11 | ADR-0153 toolchain set; tour example 17 | "/tmp (the session's temporary service, writable)" is given to every POSIX program without a grant, in a list headed "read-only". Every POSIX command can therefore read and write every other POSIX command's temporary files: a shared channel and ambient authority that the line does not show. ADR-0002 rule 7 needs a shared `/tmp` only within one make tree. Example 17 shows it, but the ADR does not discuss it as authority. | warning | State it as a known reach in "Consequences". Consider a `/tmp` per job (a fresh `tmpd` directory per command line) as an open question. Fix the "read-only" wording. |
| S12 | ADR-0153 item 3 (current directory read-only for every command) | Every command, native or POSIX and including ones with no operands, can read everything below the current directory. In `~` that is all of home; in `/` it is the whole volume. This default is not "visible in the command line" (driver 1). It is a reasonable bash-like default, but it is the largest grant most commands get, and only `grants` shows it. | warning | Say so in "Consequences" and in the `grants` topic. Consider `cwd: none` in descriptions for commands that need nothing (`echo-args`, `sleep`, `math`), which also makes INV-0153-1's "only directory connection" testable. |
| S13 | ADR-0153 "Explicit grants": "`+w PATH` grants the `tree` rights" | `+w` is the only way to get write, and it brings `remove` and `rename` over the whole tree. So the common case "let tcc write `build/`" needs a grant that can delete `build/`'s contents. Combined with S1 this makes `+w` coarse, and the ADR's open question (`+c`) only touches it. | note | Keep the open question, but give `+w` write and create and leave `remove`/`rename` to a separate `+d` (or `+c` as in `unveil`). Show the rights in words in `grants`. |
| S14 | ADR-0153 table: a `remove` operand that is a directory | `rm --recursive dir` designates `dir` as `remove`, which gives `remove` on the parent. Removing a non-empty directory needs `remove` inside `dir` as well, which the parent's connection reaches only through its subtree. That works only because of S1's over-reach. The kind for recursive removal is not defined. | note | Define it: a recursive `remove` gives `tree`-minus-`write` on the operand and `remove` on its name, and is shown as such. |
| S15 | ADR-0153, `NotFound` for a missing designated path | A missing `read`/`write` path "is entered in the table as missing, so the program reports it as not found". More important: a missing `write` operand (`write`-kind with a name that does not exist yet, for example a log file a command appends to) cannot be created at all. | note | State both behaviours, or make `write` on a missing name fall back to `create` of that one name (see S1). |
| S16 | ADR-0153 example vs tour example 17 vs ADR text "the toolchain set is shown as one line, `read (system)`" | The tour shows the set as four lines (`/bin /usr /etc read (system)`, `/tmp read and write (this session's)`, `/dev/null`, and no `/proc/self/exe`). ADR-0107 item 4 orders entries "longest first" and does not define equal prefixes. | warning | Make the ADR and the tour agree on the `grants` layout (and list `/proc/self/exe` or say why not). | S18 | ADR-0151 rule 5 and table in rule 6; INV-0151-2 | There is no `$status` word or screen line for `Terminated` with `request_kind` none: a process that called `exit_with_reason(Terminated, d)`. | S20 | ADR-0151 rule 4, `search`/`test` that answer "no" with status 1 | Under the stop rule `search TODO src; echo done` stops after a search that finds nothing, and so does any script line that greps without `if`. ## Tensions with accepted ADRs

Declared by the ADRs:

- **ADR-0096, output subset** (ADR-0154 adds SGR 2 and 22). Declared, and the handling is adequate: the change is
  additive and INV-0096-1 to -3 still hold. Under ADR-0001 rule 1 this needs the architect to accept a replacement
  sentence in ADR-0096, which ADR-0154 says.
- **ADR-0096, "programs `zosh` starts still get the console for output"** (ADR-0152). Declared. Adequate: ADR-0096
  marks it as a stage 5 limit.
- **ADR-0104 item 12, the broker spawns `/bin/sh` as the session's first process** (ADR-0153). Declared, but the
  handling is incomplete: `zosh`'s broker connection, its group for `Inherit`, and `reap` by a parent with no pid are
  not covered (S10). Where POSIX jobs live (S9) is a further tension with ADR-0104 items 1 and 4 that is not declared.
- **ADR-0105 item 9, a native shell and a POSIX session do not share a console** (ADR-0153). Declared. Adequate,
  with the stated limitation that no interactive POSIX program can run from `zosh`.
- **ADR-0105, `NotForeground` and `SIGTTIN` not reached from `zosh`** (ADR-0158). Declared. Adequate.
- **ADR-0107, a third builder of the table** (ADR-0153). Declared. Inadequate on one point: relative paths with
  `..` from a cwd that is its own entry (S6) contradict item 6 and INV-0002-4 as written.
- **ADR-0002 rule 5, the toolchain set without `/`** (ADR-0153). Declared. Adequate (ADR-0107 already narrowed rule
  5's list), but `/tmp` shared by every POSIX command (S11) should be stated with it.
- **ADR-0033, the ramdisk holds description entries** (ADR-0156). Declared. Adequate.
- **ADR-0104 item 12's `/etc/zoraya/session`** (ADR-0157). Declared as no tension. Agreed.

Not declared:

- **ADR-0104 items 1 and 4** (S9): POSIX processes' jobs are created by the broker inside the session job, not as
  sub-jobs of `zosh`, which contradicts ADR-0153 item 2 and ADR-0158 rules 1 and 5 and their invariants.
- **ADR-0107 item 6 / INV-0002-4** (S6): `..` clamped at the root of the cwd entry defeats the tour's `+r` example.
- **ADR-0004 rule 8 and ADR-0096 "Job control"** (S31): the terminal service, or the broker, holds the foreground job
  and turns Ctrl-C and Ctrl-Z into `job_signal` and `job_suspend`; in ADR-0158 `zosh` does it.
- **ADR-0046 Decision, `request_kind` none** (S18): ADR-0151's status table has no value for a `Terminated` record
  without a request kind.
- **ADR-0055 rights per connection over a subtree** (S1, S14): the operand-kind table assumes that a parent-directory
  connection can be narrowed to one name. ADR-0055 has no such narrowing, so the table grants far more than it
  shows. This is a tension between ADR-0153's stated least authority and ADR-0055's mechanism.
- **ADR-0013 rule 7 / ADR-0107 item 7, link objects** (S5): the shell's resolution of designated operands through
  link objects is not decided.
- **ADR-0001 rule 5** (S45, S46): non-Unix precedent from the postmortem, and outside evidence without a source.
- **ADR-0055 `status` request** (S17): INV-0153-1's check relies on a rights query that the protocol does not have.
