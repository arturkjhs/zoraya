## Tensions with accepted ADRs

- **ADR-0093** (one surface per connection; one-pixel frame and no other decoration; no client positioning or resizing; no message names another client; one manager channel): changed by ADR-0160 (several windows, popups, frames, resizing), ADR-0164 (`Display` in logical pixels plus scale, a new ordinal), ADR-0167 (the chooser must designate the requesting client to be centred over it, finding 14), ADR-0168 (the manager channel split between `init` and the panel, finding 12). ADR-0160 and ADR-0164 list theirs; ADR-0167 and ADR-0168 do not.
- **ADR-0094** (F12; focus changes only by button, reserved key or client end; INV-0094-1, INV-0094-2): ADR-0160 replaces F12 by the system key with a one-stage alias and adds four more ways focus changes (switcher, restore, close or minimise of the focused window, popups). INV-0094-1 is listed; INV-0094-2 and the rule sentence are not (finding 2).
- **ADR-0095** (bitmap font, exact two-colour pixels, INV-0095-1/2): ADR-0161 and ADR-0162 replace it with coverage rendering and a new reader for the screendump test; both list it. The fate of `zoraya-font` is stated unclearly (finding 19).
- **ADR-0096** (`OSC` ignored; `Size`; printable UTF-8 drawn as boxes outside ASCII): ADR-0160 relies on `Size` for resizes (listed); ADR-0162 says the "boxes outside ASCII" sentence stops being true (listed); ADR-0168 adds a title `OSC` (not listed, finding 22).
- **ADR-0097** (`init`'s GUI table, `term` and `zosh` started by `init`, restart policy, manager channel in `init`, 1024 × 768): ADR-0164 adds a second display size (listed); ADR-0167 and ADR-0169 add `chooser` and `confd` to the table (listed); ADR-0168 moves terminals and applications to the panel and shrinks `init`'s table (listed in part; the manager-channel split and the restart rules for panel-started shells are not, finding 12).
- **ADR-0092** ("one layout for the whole system", INV-0092-3): ADR-0163 makes it one active of several enabled; listed.
- **ADR-0090** (width and height 1 to 4096): 2048 × 1536 fits; ADR-0164 lists it.
- **ADR-0053** (parent-routed handles, no registry): ADR-0167's chooser hands connections at run time and ADR-0168's panel becomes a second launcher under `init`; both say this stays within the model, which is fair (Genode's child launchers). ADR-0169's `confd` is one more session service; listed.
- **ADR-0055** (`clone` with equal or fewer rights; `open` with a multi-component relative path): ADR-0167 relies on `clone` as written (fine) but INV-0167-1 contradicts the path shape (finding 3).
- **ADR-0013** (names are single components; relative paths of several components allowed): same as above.
- **ADR-0107** (namespace table built by the launcher): ADR-0167's deferred section has the desktop launcher build a POSIX program's table from the same grants, consistent; ADR-0166 driver 2 and Option B describe the table correctly.
- **ADR-0105** (a POSIX program's terminal is a window of the terminal client): ADR-0160 and ADR-0168 keep it; consistent.
- **ADR-0100/ADR-0109** (`libposix` in C plus Rust; Rust target deferred): ADR-0166 keeps the Rust target deferred and its Option A correctly notes that `pthread` is not in T1 (ADR-0005). No tension.
- **ADR-0002 rule 7** (`environ` from the spawner): ADR-0169 says nothing feeds the environment from the file; listed.
- **ADR-0010** (`publish` with replace mode): ADR-0169's atomic write of the configuration file matches rule 7 of ADR-0010; no tension.
- **ADR-0051/ADR-0052**: new ordinals and memory objects at `width × scale`; no tension beyond what ADR-0164 lists.

## Tensions with the shell design

No shell ADR exists; the shell survey (`shell/design`) decides nothing. What the desktop ADRs assume of it:

- **Grant vocabulary** (ADR-0167, ADR-0168): `zoraya-proto-file` connections with ADR-0055's rights, given at launch by the panel as the shell gives them on the command line, and shown in a launch record ("this program has: ..."). The shell survey's precedents (Plash `=>`, Deno `--allow-read=`, `unveil` letters) are all per-path grants with read/write distinctions, so the vocabulary assumed is compatible; the survey's own warning that "nothing in this survey shows a capability shell used daily" applies to the GUI launcher too and is not repeated in ADR-0167 or ADR-0168.
- **Configuration file** (ADR-0169): assumed `name = value` lines with a total parser, in "the spirit of `rc.conf`" with a `sysrc`-like command. The shell survey describes `rc.conf` as `sh` assignments (SH7); if TASK-18 adopts `sh` syntax (quoting, `$` expansion) ADR-0169's parser and its "invalid line is reported and defaulted" rule need restating. ADR-0169 says it adopts whatever TASK-18 chooses; the revisit trigger covers it.
- **Line editor** (ADR-0163): requires `zosh` to edit by character, not byte, and to compare names byte for byte; the shell survey says nothing about UTF-8 editing, so this is a new requirement on TASK-18, correctly flagged by ADR-0163 and `plan.md`.
- **Window title from the shell** (ADR-0168): the shell is expected to emit a title sequence with its current directory; nothing in the shell survey anticipates a terminal-title convention, and it crosses ADR-0096 (finding 22).
- **Conventions**: the shell survey's POLA and "one style for utilities" are matched on the desktop side by ADR-0161's one token file and ADR-0160's one frame; no contradiction found. The survey's fish principle "configurability is the root of all evil" is in tension with ADR-0169's seven settings keys only in spirit; ADR-0169 keeps the list short and does not claim otherwise.
