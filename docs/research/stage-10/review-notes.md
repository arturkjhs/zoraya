# Review notes for TASK-28 (stage 10 design)

Independent review of the survey, proposed ADR-0331 to ADR-0342, `plan.md` and `rows-to-add.md`, at commit
`56b3cd6` on branch `adr/stage-10`, 2026-11-14, as TASK-28 and ADR-0001 rule 7 ask. The material was reviewed by
three reviewers (the `opus-review` agent of `.claude/agents/`), none of which wrote any of it, each with one group of
ADRs and the survey sections behind them, in parallel. Each read the accepted ADRs its group touches, checked the
"as built" claims in the code, fetched the sources behind the claims the ADRs rest on and a sample of the rest, and
attacked the designs as a hostile program would. Nothing of the repository was built or run by the reviewers or the
author: no `make`, `cargo` or QEMU (TASK-28 forbids them). Their reports are reproduced below as written, with one
column added: the author's disposition of each finding.

**Counts.** 86 findings: 18 high, 39 medium, 29 low (reviewer 1: 8, 9, 8; reviewer 2: 4, 12, 8; reviewer 3: 6, 18,
13). 84 were accepted and fixed in the ADRs, the survey, the plan or the rows; 2 became moot through another fix
(1.24, 1.25). None was rejected.

**What the review changed in the design**, in the order of its weight:

1. **No replies from the terminal** (1.1, 1.2). The first draft replaced ADR-0096's "no answers" by replies made of
   numbers. The reviewer showed a working attack (a recipe run from inside `vi` whose replies become `vi`
   commands) and that no program of stage 10 needs a reply. ADR-0332 now keeps INV-0096-2.
2. **Nothing is suggested on the grant line, and a report is hostile data** (3.1, 3.2, 3.9). The first draft offered
   the refused path as a suggestion and showed reports as they came. A program writes its own reports, so it
   could put words on the status line and choose what three habitual keys would grant. ADR-0337's line now opens
   empty, the person types the grant, and a report is shown only if it is a plain path.
3. **Only the line in front reads keys or sets terminal modes** (1.3, 1.4). The discipline believed the group a
   program declared; a background program could read a password typed to another. ADR-0331 has the shell tag
   connections.
4. **What a repository makes git run cannot reach credentials or change git's configuration** (3.16, 3.19, 3.20).
   Children get a program's own directory to read only (ADR-0341), no credential is stored, and the network
   connection of git's helper is stated as a new decision, not an old one.
5. **`vi FILE` gets one name** (2.2, 2.1, 2.6). In the current directory the shell's merging would have given `vi`
   the directory; `vi` and `less` now say `cwd none`. nvi2 saves in place (settled from its source), not
   atomically, and needs its `:script` command removed.
6. **`sed -i` and `patch` would not have worked** (2.3): toybox saves through a renamed sibling; a patch makes them
   change the file in place.
7. **Honest options** (1.5, 1.7, 1.15, 2.5, 3.8, 3.21): the alternative of a `ttyd` per window, netbsd-curses, an own
   `TERM` name, Vim, the status line without a grant line, and a `.git`-only grant are each restated with their
   best evidence, and three of them are put to the architect as open choices.
8. **In a room's own terminal the grant line can give nothing; untrusted rooms and the serial console are out of
   stage 10** (3.3, 3.4, 3.11, 1.12).

**One defect of shipped code** came out of the review and is outside this task's files (3.9): the hint `zosh`
prints after a refused path shows the path unquoted and unfiltered, so a directory whose name holds `;` produces a
`to allow it:` line that runs another command if pasted. ADR-0337 item 2 fixes it when built; it is reported to
the architect for the backlog.

### The question I was asked to settle: does nvi2 write the file in place? (2)

**Yes, in place.** nvi2 `common/exf.c`, `file_write` (master and v2.2.2 identical here): it computes
`oflags = O_CREAT | O_WRONLY | (LF_ISSET(FS_APPEND) ? O_APPEND : O_TRUNC)` and calls `open(name, oflags, 0666)` on the
edited name itself (exf.c:830–840), then writes the buffer through `fdopen`. There is no rename anywhere in the write path;
`ex/ex_write.c:256`'s `scr_rename` renames the screen's title, not a file. What else it does on a save: `stat(name)`
before writing (mtime and inode check, exf.c:803–826); a backup copy only if the `backup` option is non-empty (default
empty, options.c:60); `file_lock` (`flock`) on a write to another name, only if the `lock` option is set (exf.c:869,
1486); on `:w!` after `EACCES`, a `chmod` of the file to add owner write and an `fchmod` back (exf.c:842–862). A file that
does not exist when `vi` starts is backed by `mkstemp` of `vi.XXXXXXXXXX` in the `directory` option, which is `$TMPDIR` or
`/tmp` (exf.c:172–186, options.c:358). So driver 3 holds for files outside the current directory; see finding 2 for the
current directory, and finding 6 for what in-place writing costs.

What the survey and ADR-0335 say nvi needs, against nvi2's source: `dbopen` from DB 1 (CMakeLists.txt:219–224, yes);
curses and terminfo (yes, lines 154–169); iconv optional (`USE_ICONV`, yes); the recovery directory
`/var/tmp/vi.recover/` (CMakeLists.txt:239; `rcv_tmp` makes it with `mkdir(dp, 0)` and `chmod` to 01777, recover.c:135–141,
yes); mail through `_PATH_SENDMAIL` (recover.c:828, yes); `flock` (exf.c:1497, yes, behind the `lock` option). Not in the
ADR: `openpty` and `setsid` in `ex/ex_script.c`, compiled unconditionally (finding 1); `__b64_ntop`/`__b64_pton` in
recover.c (gone with recovery); CMake 3.17 and Ninja to build (finding 7); `select` on the terminal (cl_read.c:183, covered
by ADR-0342 item 5); `getlogin`/`getpwnam`/`getpwuid` for `~` (util.c:151, covered by item 7); `nl_langinfo(CODESET)`
(conv.c:43); `mmap` of a tags file with `PROT_WRITE` (ex_tag.c:1042: fails cleanly on Zoraya, tags then do not work).
