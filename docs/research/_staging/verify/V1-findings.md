## Summary

15 items: 1 pass (DM-006), 12 fixed, 2 downgraded (DM-009, DM-012), 0 flagged. Every cited source in the slice was fetched (LWN items after a rate-limit retry). Five new primary sources added (S2000–S2004).

Classification changes: DM-009 right-at-the-time-wrong-now → tradeoff (Hardy shows the confused-deputy failure on a 1970s time-sharing system, when capability systems already existed); DM-012 right-at-the-time-wrong-now → tradeoff (uncited steelman, no evidence the constraint changed rather than the cost becoming visible). The other right-at-the-time-wrong-now labels (DM-001, -002, -003, -004, -006, -010) were kept because the sources document both the original constraint (single-threaded processes, small machines, users-vs-users threat model) and the change (threads/SMP, single-user machines running untrusted code).

Most serious problems: (1) DM-011 misstated OpenBSD pledge: the source says pledged processes cannot *set* setuid bits, not that setuid bits are ignored on exec; it also attributed to the Plan 9 paper a claim it does not make. (2) Several claims were cited to sources that do not contain them: PEP 446 pipe hangs (DM-002), setsid "double-fork to detach" (DM-005), Windows handle-based waiting in S113 (DM-005), the git option-injection mechanism in S133 (DM-008), SIP recovery in S215 (DM-012), and libc fragility in the seccomp docs (DM-014). (3) Wrong version number: CLONE_PIDFD is 5.2, not 5.3 (DM-003). (4) Paraphrase drift in attributions (Dolstra's root causes, Kerrisk's reason for CAP_SYS_ADMIN creep, "reference policy", "SEAndroid needed middleware MAC because of zygote"). Steelman additions: Drepper's counter-arguments in DM-001; Hardy's evidence that capability systems came out smaller (DM-009). Remaining [unverified] markers: Mach task/thread split (DM-004), DOS origin of the Windows command line (DM-008), libc fragility of seccomp (DM-014), plus the original markers in DM-008/014/015.
