# ADR-0228: TLS in each program, with the roots, the clock and the entropy from the system

- **Status:** accepted
- **Date:** 2026-11-04
- **Depends on:** ADR-0100, ADR-0109, ADR-0153, ADR-0166, ADR-0220, ADR-0221, ADR-0222, ADR-0223, ADR-0224, ADR-0226, ADR-0227, ADR-0229
- **Evidence:** CP-15, CP-27, DM-048, alternatives-postmortem.md#plan-9--inferno, network/survey.md#bearssl, network/survey.md#container-and-agent-sandboxes, network/survey.md#embedded-tls, network/survey.md#mbed-tls, network/survey.md#plan-9s-tls-filters-and-key-agent, network/survey.md#rustls, network/survey.md#the-root-store-and-its-licence, network/survey.md#what-a-fetch-over-https-needs

## Context

Almost every real use of the network is HTTPS. A program fetching over HTTPS needs a TLS client, trust anchors, the
server's name, the date and entropy (`network/survey.md#what-a-fetch-over-https-needs`). Two questions: *where* TLS
runs, in each program or in a service that terminates it, and *which library*. The survey's candidates: rustls (TLS
1.2 and 1.3, Rust, permissive, builds without `std` on the pinned toolchain but needs a crypto provider that does, and
the two that build without a C toolchain are new or alpha, `network/survey.md#rustls`); embedded-tls (TLS 1.3 only,
`no_std`, pulls ring through its verifier, `network/survey.md#embedded-tls`); BearSSL (C, MIT, TLS 1.2, no allocation,
takes the time explicitly, beta, `network/survey.md#bearssl`); Mbed TLS (C, Apache or GPL, TLS 1.2 and 1.3, explicit time
and entropy macros, `network/survey.md#mbed-tls`). The root store everyone ships is Mozilla's, packaged under
`CDLA-Permissive-2.0`, a licence outside `CLAUDE.md`'s list (`network/survey.md#the-root-store-and-its-licence`).
ADR-0226 and ADR-0227 supply the date and the entropy; ADR-0223's `connect(Name)` supplies the name the certificate
must match.

**What is measured.** The `cargo check` results (`network/survey.md#rustls`, `network/survey.md#embedded-tls`).
Nothing on Zoraya.

**What is assumed.** That the first HTTPS programs are curl (C, through `libposix`) and a native `fetch` (Rust); that
client certificates are not needed by any program in scope.

## Decision drivers

1. **No plaintext in a shared component unless the design needs it** (CP-15): what a program sends over TLS should be
   readable by that program and its peer, not by `netd`.
2. **The name the certificate must match is the name in the grant** (ADR-0220, ADR-0223): the grant and the identity
   should be the same string.
3. **Permissive licences only** (`CLAUDE.md`), for code and for data.
4. **C programs link their own TLS anyway** (ADR-0100's model: musl and the ports are C): whatever is chosen for
   native programs, curl needs a C library in the sysroot.
5. **Small trusted base** (DM-048): a TLS service is a parser of hostile bytes holding every program's session keys.
6. **The surface stays bounded** (CP-27): one TLS library per language, not one per program.

## Considered options

### Option A: A TLS library in each process, with the system's roots in a file (the Unix baseline: OpenSSL and `/etc/ssl`)
- **Description:** Every program links its TLS library of choice and reads the root store from a well-known path.
- **Evidence for:** How every Unix program works; the peer's identity is checked by the program that cares.
- **Evidence against:** Each program picks a library and a root store path (ambient, unless the path is a grant);
  nothing supplies a clock or entropy by design.
- **Cost:** *(estimate)* Nothing to build beyond ports.
- **Precedent:** Unix.

### Option B: TLS in each program, one library per language, roots, clock and entropy from the system
- **Description:** Native programs use a `zoraya-tls` crate over rustls 0.23 without `std`, with a crypto provider that
  builds for `aarch64-unknown-none` (graviola is the candidate; rustls-rustcrypto needs `std` today), a
  `TimeProvider` from ADR-0226's base, a random source seeded from ADR-0227's service, and roots from a read-only
  `/system/tls/roots` entry. POSIX programs link a C library from the sysroot (BearSSL first for curl, Mbed TLS when
  TLS 1.3 is needed), built as ports (ADR-0109), with the time from `time()` and entropy from `getrandom`. The roots
  entry is added to a program's table whenever it holds any network grant (ADR-0224), so a program that may reach
  the network may read the public roots and nothing else.
- **Evidence for:** Drivers 1 to 6: `netd` sees ciphertext; each program checks the name it was granted; one crate
  and one C library; the system supplies the three things the survey says every validator needs. It is how programs
  on general-purpose systems do TLS `[assumption: general knowledge, no source in the files]`, and how the agent
  sandboxes' proxies leave TLS to the tool by default (`network/survey.md#container-and-agent-sandboxes`: the proxy
  "enforces the allowlist based on the requested hostname and, by default, does not terminate or inspect TLS
  traffic").
- **Evidence against:** Two TLS implementations in the image (Rust and C); the Rust provider question is open
  (`network/survey.md#rustls`: ring needs a C toolchain with target headers, graviola is "very new", rustls-rustcrypto
  is alpha and `std`-only); TLS code in every networked program, so a TLS bug is in each; no central place to see
  what a program fetched.
- **Cost:** *(estimate)* `zoraya-tls` 500 lines over rustls plus a provider recorded in `docs/dependencies.md`; the
  BearSSL port with its shim (as musl's, ADR-0100); the roots file and its licence decision.
- **Precedent:** Every general-purpose system `[assumption]`; rustls's own use is in programs, by its API's shape
  (`network/survey.md#rustls`).

### Option C: A TLS service that terminates TLS for programs
- **Description:** `connect(..., tls: true)` makes `netd` (or a `tlsd` beside it) do the handshake, validate the chain
  against the roots and the clock, and hand the program a plaintext stream; the program never sees TLS. Plan 9's
  `tlsclient`, which "dials address, starts TLS, and then relays between the network connection and standard input
  and output", is the ancestor (`network/survey.md#plan-9s-tls-filters-and-key-agent`, from the system of
  `alternatives-postmortem.md#plan-9--inferno`); Claude Code's `network.tlsTerminate` is the proxy form
  (`network/survey.md#container-and-agent-sandboxes`).
- **Evidence for:** One TLS implementation; roots, clock and entropy in one place; the grant's name and the
  certificate's name are checked by the same component, which could *guarantee* that a stream granted as
  `api.example.org` is authenticated as such; a supervisor could audit plaintext.
- **Evidence against:** Driver 1 and 5: the service holds every session's keys and plaintext, the largest possible
  prize for a compromise of the one process that already parses every frame; C programs would still link their own
  TLS (curl does not know how to not do TLS), so the service would serve native programs only; client certificates
  would put the program's keys in the service.
- **Cost:** *(estimate)* rustls in `netd` plus the protocol flag; the C side unchanged.
- **Precedent:** Plan 9's `tlssrv` and `tlsclient` (`network/survey.md#plan-9s-tls-filters-and-key-agent`),
  TLS-terminating proxies.

### Option D: TLS in each program, keys in an agent (Plan 9's factotum)
- **Description:** As B, with a key agent holding client keys and performing the proof on request, so a program never
  holds its long-term key: Plan 9's `factotum`, the user's authentication agent whose secret attributes are never read
  back (`network/survey.md#plan-9s-tls-filters-and-key-agent`).
- **Evidence for:** The right answer for client certificates and SSH keys later.
- **Evidence against:** No program in scope needs a client key; it is B plus a service that waits for a user.
- **Cost:** *(estimate)* A service and a signing protocol.
- **Precedent:** Plan 9's `factotum` (`network/survey.md#plan-9s-tls-filters-and-key-agent`); SSH agents
  `[assumption: general knowledge]`.

## Recommendation

### Decision

Accepted as recommended (architect, 2026-11-04), with two answers: the root store is Mozilla's, shipped as data under `CDLA-Permissive-2.0`, which `CLAUDE.md`'s licence rule now allows for data files only; the crypto provider is settled by plan task N1, which tries ring first, built with the clang the toolchain already has (ADR-0109), with BearSSL as the fallback for native programs too.

The original recommendation follows.

**Recommendation (not a decision): Option B**, with Option D as the recorded path for client keys.

1. **Native: `zoraya-tls`.** A `no_std` crate over rustls 0.23 (`default-features = false`, `tls12`,
   `custom-provider`), with: a `TimeProvider` returning ADR-0226's base plus the monotonic clock; a `SecureRandom`
   that is a generator seeded from ADR-0227's connection and reseeded; the verifier from `rustls-webpki` with the
   roots read from `/system/tls/roots`; and the server name set from the `Name` the program connected to (ADR-0223).
   The crypto provider, by the Decision: **ring** first, built with the clang the toolchain already has (ADR-0109's
   `tools/zcc` with the musl sysroot supplies the C headers the survey's check lacked, `network/survey.md#rustls`),
   in plan task N1; if that fails, **BearSSL** is the fallback for native programs too, through a C-ABI binding over
   the same port the POSIX side uses; graviola and rustls-rustcrypto stay recorded in the survey as candidates. The
   outcome is a dependency decision recorded in `docs/dependencies.md` with the check that justified it. The crate offers a blocking `connect` over ADR-0222's stream ends
   and the unbuffered `UnbufferedClientConnection` API, since the buffered one needs `std`.
2. **POSIX: BearSSL** as a port in the sysroot (MIT), configured with the time from `time()` and entropy from
   `getrandom`, so that curl builds with `--with-bearssl`; Mbed TLS (under its Apache-2.0 option) is the port to add
   when a program needs TLS 1.3, since BearSSL has none.
3. **Roots.** `/system/tls/roots`, a file of PEM certificates in the system image, read-only, added by the shell to the
   table of any program with a network grant (ADR-0224 item 1: the grant implies this entry, whose path is the
   `tls.roots` setting the shell declares, ADR-0229; `grants` shows it as `/system/tls/roots    read (with the
   network)`). Its content, by the Decision: Mozilla's store, shipped as data under
   `CDLA-Permissive-2.0`, which `CLAUDE.md`'s licence rule allows for data files only, recorded in
   `docs/dependencies.md` as data; a person may still point `tls.roots` (ADR-0229) at a file of their own.
4. **Names.** A program verifies the name it connected to; `zoraya-tls` takes it from the `connect` call, so a program
   cannot connect to one name and verify another by mistake.
5. **Not now.** Client certificates (Option D), session resumption across programs, OCSP and CRLs, TLS in `netd`.

**Examples.**

```
~/proj> fetch https://example.org/ -o page.html
~/proj> fetch https://expired.example.org/
fetch: expired.example.org: certificate expired on 2026-01-01
~/proj> grants fetch https://example.org/ -o page.html
fetch gets:
  ...
  net: example.org:443     reach (operand URL)
  /system/tls/roots        read (with the network)
```

**Tensions with accepted ADRs.**
- *ADR-0166* keeps native programs `no_std`: rustls without `std` and its provider must too (the measured check
  covers rustls; the provider is the open question).
- *ADR-0100*/*ADR-0109*: a second and third C port (BearSSL, later Mbed TLS) under ADR-0109's port rules, recorded in
  `docs/dependencies.md`.
- *`CLAUDE.md`'s licence rule*: the root store's `CDLA-Permissive-2.0` is outside the list; item 3 makes it a decision.
- *ADR-0153 rule 1*: the roots entry is added by a network grant, not by default.

### Effect of the vision
For target 2 the agent's traffic is opaque to `netd`, which protects the agent's data from a compromised stack and
also hides it from a supervisor who wanted to read it; the latter is Option C's appeal, and ADR-0224's grant hint and
the scope are what the supervisor sees instead. Target 3: a browser would need TLS 1.3 natively, which rustls has.
Threads: none.

## Consequences
- **Positive.** Programs own their secrets; one crate, one C library; the system supplies the roots, the date and the
  randomness, so a program needs no configuration to fetch a page.
- **Negative.** TLS code in every networked program; the Rust provider is unsettled; the root store's licence needs a
  decision; BearSSL is TLS 1.2 only.
- **Follow-up.** The provider check for `aarch64-unknown-none`; `zoraya-tls`; the BearSSL port and curl's build; the
  roots file; `fetch` (ADR-0230's W12 client).

## Invariants
- **INV-0228-1.** A connection to a name whose certificate does not match it, is expired against the base, or chains
  to no root in `/system/tls/roots` fails before any application byte is sent. *Check:* host tests of `zoraya-tls`
  against a scripted TLS server with a wrong name, an expired certificate and an unknown root; an in-QEMU test of
  `fetch` against the runner's test server with the same three (ADR-0230).
- **INV-0228-2.** `netd` holds no TLS state: its process has no TLS crate and no key material. *Check:* `cargo
  metadata` over `user/`'s dependency graph shows `zoraya-tls` and rustls absent from `netd`'s.
- **INV-0228-3.** `/system/tls/roots` is in a program's table only with a network grant, read-only. *Check:*
  INV-0153-1's enumeration with and without `+net`.

## Open questions
- The crypto provider for `aarch64-unknown-none`: *settled by the Decision* as N1's check of ring with the
  toolchain's clang, BearSSL as the fallback.
- The root store's licence and content: *settled by the Decision*.
- Whether curl should be built with Mbed TLS from the start for TLS 1.3, at the cost of the larger port.
- Note (N5 review, decided): "read-only" held only for a program's own table: a console shell holds the volume's root,
  and a `fetch URL -o /system/tls/roots` it granted could replace the trust store. **Decided by the architect** (his
  instruction of the follow-up task `work/system-ro`, transcribed by an agent, not an edit of the "Architect's
  decision" section): `/system` is read-only at run time for everyone, the console shell included; `fsd` serves it
  read-only and no grant can give write to it (`+w /system` is refused, with a hint); it changes only when the image
  is built (later: an explicit system-update path, its own ADR). Built and checked by ADR-0289 item 8 and INV-0289-4
  (`cargo test -p zoraya-fs-service --test service`, `make test-files`).

## Revisit triggers
- A program in scope that needs client certificates: Option D.
- A measured need to audit an agent's traffic: Option C for untrusted rooms only, as an opt-in the room's record shows.
- rustls 0.24's provider split lands: the `custom-provider` feature becomes the only form.

## Architect's decision

Accepted 2026-11-04. Decided by the architect; recorded by an agent at the architect's request. The root store: ship Mozilla's store as data, and `CLAUDE.md`'s licence rule gains `CDLA-Permissive-2.0` for data files only. The crypto provider: plan task N1 tries ring first, built with the clang the toolchain already has, and BearSSL is the fallback for native programs too; item 1 and `plan.md` record it.
