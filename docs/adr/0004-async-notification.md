# ADR-0004: Asynchronous notification without Unix signals (native side)

- **Status:** accepted
- **Date:** 2026-10-25
- **Depends on:** ADR-0002, ADR-0003
- **Evidence:** CP-02, CP-06, CP-07, CP-10, CP-12, CP-25, X-3, X-10, X-12, DM-004, DM-005, DM-017, DM-027, DM-059, DM-070, DM-077, DM-100, DM-130, GR-003, alternatives-postmortem.md#fuchsia--zircon-incl-starnix, task-02/callsite-analysis.md#feature-2-signals, task-02/callsite-analysis.md#feature-4-tty-and-job-control, task-02/conflict-impact.md#x-3-no-asynchronous-interruption-cp-10-vs-posix-signal-semantics, task-02/posix-surface.md#key-observations, task-02/posix-surface.md#linux-syscall-surface-m2, task-02b/callsite-analysis.md#3-signal-handlers-and-masks-during-parallel-builds, task-02b/callsite-analysis.md#4-cleanup-on-interruption, task-02b/callsite-analysis.md#what-the-mapping-exercise-shows-estimate, task-02b/conflict-impact.md#cp-25--cp-07-terminal-rights-and-job-containment, task-02b/conflict-impact.md#open-questions-the-data-frames-but-cannot-answer, task-02b/conflict-impact.md#x-3-no-asynchronous-interruption-cp-10-vs-posix-signal-semantics, task-02b/event-timelines.md#w10-background-jobs-wait-concurrent-pipelines-run-w10-parallel-r1, task-02b/event-timelines.md#w9a-ctrl-c-run-w9-int-d15-r1, task-02b/event-timelines.md#w9b-sigterm-to-the-top-level-make-run-w9-term-d15-r1, task-02b/parallel-surface.md#interrupted-system-calls, task-02b/parallel-surface.md#interruption-what-happens-to-the-build-w9, task-02b/parallel-surface.md#signals-actually-delivered

## Context

CP-10 says the native ABI delivers events as messages or wait results, never by interrupting a running thread, and keeps an uncatchable kill. Signals are classed a *mistake* (DM-017). The POSIX personality must still emulate the signals the toolchain uses (X-3). This ADR decides how native programs learn about **child exit**, **faults** and **user interrupt**, how a **termination request** reaches a group of processes, how each process gets its chance to clean up, and how "terminated by interrupt" appears in the exit status a parent reads. The general waiting mechanism (the port) is ADR-0006.

**Division of labour with ADR-0006.** ADR-0004 owns the *event sources and their semantics*: the exit record, request signals and their dispositions, delivery to a job, exception delivery, the inherited attribute block, and the personality's signal dispositions and delivery rule. ADR-0006 owns the *wait primitive*: ports, subscriptions, packets, deadlines, object signal sets, cancellation, and the personality's implementation of `pselect`, `sigsuspend`, `wait*` and `nanosleep` as port waits, including the jobserver. Where this ADR says "delivered at a wait point", the wait point is an ADR-0006 port wait.

**What is measured.**

- Signals delivered in core runs (`task-02/conflict-impact.md#x-3-…`, `tools/posix-surface/results/signals-delivered.md`): SIGCHLD child-exited 3,751; SIGCHLD child-killed 1; SIGINT from the terminal 1; SIGINT raised by dash itself 1. All three deliveries other than SIGCHLD-child-exited are in W5, the interactive session. In T1–T3 the only signal is SIGCHLD and no system call was interrupted.
- Under `make -j` the picture is the same: SIGCHLD only, to the make that started the child, now as the main wake-up of every waiting make (`task-02b/parallel-surface.md#signals-actually-delivered`; `task-02b/conflict-impact.md#x-3-…`, "Under -j, SIGCHLD becomes make's main wake-up"). The SIGCHLD handler only increments a counter (`job.c:615`).
- Handlers installed (`tools/posix-surface/results/summary-tables.md`, "Signal handlers installed"): dash SIGCHLD and SIGINT, plus SIGHUP/SIGTERM/SIGPIPE from configure's `trap` lines in T2; GNU make SIGCHLD plus the fatal set HUP INT QUIT PIPE TERM USR1 XCPU XFSZ; pdpmake HUP, TERM; toybox USR1, USR2 (never delivered); clang/lld 15 signals for crash reporting (T3 only). Most `rt_sigaction` traffic is musl resetting dispositions in spawned children (`task-02/posix-surface.md#linux-syscall-surface-m2`).
- Ctrl-C (W9a, 9/9 runs): the tty driver sends SIGINT to every process of the foreground group at once; nobody forwards it; the 4 recipe processes die by default action; each make, inside its handler, deletes the partial target of its running recipe, reaps its children with a blocking `wait4`, and re-raises SIGINT on itself; deaths propagate bottom-up; dash reaps the top make, sees "killed by SIGINT", takes the terminal back and interrupts itself to abandon the command line; `$?` = 130 (`task-02b/event-timelines.md#w9a-…`).
- SIGTERM to the top make (W9b, 9/9): SIGTERM goes to one process; make forwards it to its direct children one level at a time (`commands.c:544`); cleanup is the same; `$?` = 143. Forwarding takes milliseconds, during which a lower make started a new recipe in 1/9 runs and had to kill it; in 4/9 runs a nested SIGCHLD interrupted the handler's own `writev`, which was restarted. Ctrl-C showed neither effect (`task-02b/event-timelines.md#w9b-…`, `#stability-…`).
- Interrupted system calls appear only where the program asked: `pselect6` with an atomic mask, `sigsuspend`; plus blocking `wait4` calls that the never-returning handler abandons (`task-02b/parallel-surface.md#interrupted-system-calls`). No program saw `EINTR` as an error it had to retry.
- Exit status is an interface: every make re-raises the signal rather than exiting with a code, because dash abandons the rest of a command line only on death by SIGINT (`task-02b/event-timelines.md#w9a-…`, "Exit status is the interface"; `task-02b/callsite-analysis.md#4-cleanup-on-interruption`, re-raise is `emulate`).
- Shell parallelism (W10): `wait` is `sigsuspend` + SIGCHLD + `wait4`; background jobs of a non-job-control shell set SIGINT/SIGQUIT to ignore before exec; `yes | head` kills the writer with SIGPIPE and the shell treats that as normal (`task-02b/event-timelines.md#w10-…`).
- Job control in T0 only: `tcsetpgrp`, `tcgetpgrp`, `setpgid`, 15 `TIOCSPGRP` ioctls; no T1/T2 program uses process groups (`task-02/callsite-analysis.md#feature-4-tty-and-job-control`). W5 exercised a background job, `jobs` and Ctrl-C of a foreground `sleep`, not Ctrl-Z.
- What the signal sites need, by purpose (`task-02/callsite-analysis.md#feature-2-signals`): child-exit wakeup (make restructure, dash emulate); death-by-signal propagation (emulate); termination cleanup (make, pdpmake, toybox: restructure 15–30 lines, "needs a termination requested hook"); fault capture (tcc `-run`, restructure, not exercised); job control, `kill` builtin, `trap`, inherited ignores (emulate in shells).

**What is assumed.** Interrupts arriving while a make is in `fork`/`exec` or `$(shell)` were not measured; only waits were hit (`task-02b/conflict-impact.md#open-questions-…`). Whether make's cleanup runs correctly outside signal context is an M7 estimate (about 30 lines), not a patch. SIGWINCH/SIGTSTP to full-screen programs: not exercised.

**Forces from TASK-01.** Async handlers may only call async-signal-safe functions; regreSSHion (CVE-2024-6387) is the canonical failure (DM-017). Fault delivery (SIGSEGV) is the part of the original design Brown calls well handled (DM-017). Starnix names asynchronous signal handlers as having "no Fuchsia equivalent" and still works on them five years later (`alternatives-postmortem.md#fuchsia--zircon-incl-starnix`). NT console control handlers run on a fresh thread the system creates (DM-017, S339). seL4 delivers asynchronous events as notification objects a thread waits on (DM-017). Plan 9's rio turns DEL and hangup into *notes* delivered to a process named at window creation (DM-070). Process groups and sessions are a two-level hierarchy designed for one physical terminal; keeping a job alive after logout needs ritual (DM-070). Job objects give tree-wide termination that process groups cannot (DM-100); `cgroup.kill` had to handle forks concurrent with the kill (DM-100). `pthread_cancel` and `EINTR` are the cost of asynchronous interruption at the library level (DM-059, DM-027).

## Decision drivers

1. **The toolchain uses signals as wake-ups for waits, not as interruption** (`task-02b/conflict-impact.md#x-3-…`, "Out: parallel builds need asynchronous signal delivery … during normal operation"). Child exit is an exit event on a process handle (CP-06, DM-130).
2. **Interrupt must reach a whole job at once.** Group delivery had no window; one-level forwarding had one in 1/9 runs (`task-02b/conflict-impact.md#x-3-…`, "Out: user interrupt needs signal forwarding by programs"). CP-07 asks for "kill the whole tree"; the data shows the toolchain uses it only through the terminal's process group (`task-02b/conflict-impact.md#cp-25--cp-07-…`).
3. **Each process must get a chance to clean up.** No partial target was left behind in 36/36 runs; each make deleted the partial target of its running recipe and waited for its children before dying (one SIGTERM run had only 3 to delete because a make had killed its recipe before the target existed) (`task-02b/parallel-surface.md#interruption-what-happens-to-the-build-w9`). An uncatchable kill alone would leave partial targets.
4. **"Terminated by interrupt" must be distinguishable from "exited with a code" at every level** (`task-02b/conflict-impact.md#x-3-…`, "Constrained: the exit status as an interface"). The exit record needs a reason field (CP-06, CP-12).
5. **Default actions must work without the target's cooperation.** The 4 `mktab` recipes and the W5 `sleep` died by default action with no handler (`task-02b/event-timelines.md#w9a-…`, `tools/posix-surface/results/signals-delivered.md`). So dispositions cannot live only in the target's library.
6. **"Ignored on entry" is inherited state.** Background jobs ignore SIGINT/SIGQUIT before exec; make and pdpmake keep a disposition that was ignored on entry (`task-02b/callsite-analysis.md#3-…`; `task-02/callsite-analysis.md#feature-2-signals`, "Inherited dispositions"). The spawn attribute block (ADR-0003 rule 1) must carry it.
7. **No asynchronous handler in the native ABI** (CP-10, DM-017, DM-059): events are wait results. The measured delivery points are all waits (driver 1, `task-02b/parallel-surface.md#interrupted-system-calls`), so a wait-point emulation covers the data.
8. **Faults are synchronous and different** (DM-017): they need an upcall or fault IPC (CP-10 cost). Only tcc `-run` and the T3 crash handlers use them, and no workload triggered a fault (`task-02/conflict-impact.md#x-3-…`, "Unconstrained: synchronous fault delivery").
9. **`EINTR` disappears natively** if there is no asynchronous interruption; the personality keeps it only where POSIX programs ask for it (DM-027; the data: `pselect6`, `sigsuspend`).

## Considered options

### Option A: Unix signals in the kernel (baseline, "do what POSIX does")

- **Description:** The kernel keeps per-process dispositions, masks and pending sets; delivery interrupts a thread to run a handler; default actions terminate, stop or ignore; `kill`, process groups and `SIGCHLD` work as in Linux.
- **Evidence for:** Every measured program works unchanged, including the parts classed `emulate`: dash's `trap`, `kill`, job control, inherited ignores, re-raise (`task-02b/callsite-analysis.md#3-…`, 37 dash sites). Synchronous faults are handled well by the same mechanism (DM-017, Brown). Signals are what every shell and daemon expects (DM-017, "Why it was not fixed").
- **Evidence against:** DM-017 (*mistake*): async-signal safety, regreSSHion, one-shot races, `EINTR` (DM-027), thread-directed vs process-directed delivery (DM-004), `signalfd` needing the mask to survive `exec` (DM-130). It contradicts CP-10. The measured use is wake-ups and cleanup hooks, which do not need interruption (driver 1).
- **Cost:** *(estimate)* Zero emulation cost. Permanent kernel complexity (masks across exec, per-thread pending sets) and every library in the native stack must be async-signal-safe somewhere.
- **Precedent:** Unix. Works; it is the entry.

### Option B: Events as wait results on handles, with kernel-held request dispositions and job-wide delivery (non-Unix precedents: NT waitable objects and console control events, seL4 notifications, Zircon signals and exception channels)

- **Description:** No asynchronous handlers. Three native mechanisms: (1) *exit records* on process objects, waited on through the port (CP-06; DM-005: an NT process handle stays valid after the process ends, the object becomes signalled and any handle holder can wait on it); (2) *request signals* on process objects: `Interrupt`, `Terminate`, `Hangup`, `Quit`, `Custom(n)`, each with a kernel-held disposition per process of `Terminate` (default), `Ignore` or `Deliver`; a delivered request is a signal on the process's own handle, observed at a port wait; a `Terminate` disposition ends the process with an exit record saying so, without running user code; `job_signal(job, request)` applies the request to every process in the job tree atomically with respect to concurrent spawns; `kill` stays uncatchable; (3) *exception channels* bound to a process or job, to which a fault is delivered as a message while the faulting thread stays suspended (Zircon model, DM-130 alternatives; seL4 fault IPC, DM-017). NT's console control handler, which runs on a fresh thread, is the precedent for delivering interrupt without interrupting (DM-017, S339).
- **Evidence for:** It is exactly the shape the data rules in: child exit as an event that also wakes a pending readiness wait; terminal interrupt to every process of the foreground job; termination requests to single processes; an exit reason parents can read (`task-02b/conflict-impact.md#x-3-…`, "In: a native ABI without asynchronous interruption"). Kernel-held dispositions satisfy driver 5 (default actions without cooperation) and driver 6 (inheritance by attribute). Job-wide delivery satisfies driver 2 and DM-100's concurrent-fork lesson. The M7 estimate says make's handler body is cleanup code that can run from the main wait, and that the event model *removes* the 27 restructure sites (about 45 lines), most of which exist to make asynchronous signals safe (`task-02b/callsite-analysis.md#what-the-mapping-exercise-shows-estimate`).
- **Evidence against:** Fidelity: a POSIX program in a compute loop with a `Deliver` disposition does not see the request until it reaches a wait point or a `libposix` entry; Linux would run the handler immediately. No measured program hit this, but it was not looked for (what is assumed). Starnix lists async handlers as a hard part and did build them (`alternatives-postmortem.md#fuchsia--zircon-incl-starnix`). Kernel-held dispositions are a small signal-like table in the kernel, which is more than CP-10's "events are messages" strictly implies. Zircon's one-shot waits can miss edges (DM-130 cost); ADR-0006 must avoid that.
- **Cost:** *(estimate)* Kernel: exit record, four fixed request kinds plus a small table of custom slots, each with a 2-bit disposition, job fan-out, exception channels; a few hundred lines. Library: `libposix` dispositions, pending set and wait-point delivery; the hard part is the interactive shell (job control), which the data already locates there. Compatibility: everything measured in T0–T2 (walked through in ADR-0006). Performance: no handler context switches; one port packet per event.
- **Precedent:** NT (process objects signalled on exit; console control events; no general async signal for IPC, DM-017), seL4 (notifications), Zircon (object signals, exception channels; Starnix emulates Linux signals on top and reports it as hard).

### Option C: Interrupts delivered on a fresh kernel-created thread (NT console-control model)

- **Description:** As Option B for exit records and exceptions, but a request with `Deliver` disposition starts a new thread in the target process at a registered entry point, instead of setting a signal the process waits for. The main thread is never interrupted; the handler thread runs concurrently.
- **Evidence for:** True asynchrony without interrupting a running instruction stream: a compute-bound program reacts immediately, which closes Option B's fidelity gap. NT uses it for console control events such as Ctrl-C (DM-017, S339). It needs no async-signal-safe rules, only ordinary thread synchronisation.
- **Evidence against:** POSIX handlers assume they run on the interrupted thread: dash's `onint` re-raises SIGINT so that a non-interactive shell dies by it (`task-02b/callsite-analysis.md#3-signal-handlers-and-masks-during-parallel-builds`; that it unwinds the interpreter with `longjmp`-style error raising first is `[outside evidence: dash source, error.c]`), and make's `fatal_error_signal` reaps children and never returns (`task-02b/callsite-analysis.md#4-cleanup-on-interruption`). A handler on another thread cannot unwind the main thread, so `libposix` would still have to convert the event into a wait-point delivery for those programs, which is Option B plus a thread. "A per-thread fresh handler moves the problem to ordinary thread synchronisation" (DM-017 cost). T0–T2 are single-threaded (`task-02/posix-surface.md#key-observations`); adding a thread to each POSIX process changes that.
- **Cost:** *(estimate)* Kernel: thread injection into a target process (a cross-process primitive, ADR-0003 Option D territory). Library: both mechanisms. Compatibility: no better than B for the measured programs; better for native programs that want immediate reaction.
- **Precedent:** NT consoles. Works for Windows programs written for it; it is not a POSIX emulation strategy.

### Option D: Typed asynchronous upcall as a native primitive (signals without the mistakes)

- **Description:** Keep one kernel primitive that forces a thread into a registered entry point with a typed message, usable only by a holder of the thread handle with an `interrupt` right (CP-02), with a defined safe subset for the upcall. The personality uses it to run POSIX handlers exactly where Linux would.
- **Evidence for:** Exact signal emulation, including handlers in compute loops and `tcc -run` fault capture on the faulting thread (`task-02/callsite-analysis.md#feature-2-signals`). The Starnix experience says this is what binary compatibility eventually needs (`alternatives-postmortem.md#fuchsia--zircon-incl-starnix`). Capability gating confines it: a process that does not hand out its thread handles cannot be interrupted. Deferred delivery at declared points *can* be implemented correctly: musl decides precisely whether a syscall completed by checking the saved program counter against labels, which DM-059 says "shows deferred cancellation can be implemented without the glibc race".
- **Evidence against:** It is DM-017's mechanism with a rights check: every native library must again be upcall-safe at every instruction, or the upcall must be restricted to points the thread declares, at which point it is Option B. It contradicts CP-10 directly. `pthread_cancel`'s history shows that "safe only at declared points" is hard to get right in practice: glibc's cancellation race was reported in 2011 and fixed only in glibc 2.41 (DM-059). The data gives no measured program that needs it in T0–T2 (driver 1, driver 7).
- **Cost:** *(estimate)* Kernel: thread interruption with register save/restore and a return path, plus the safety subset; the hardest primitive in this ADR. Library: handler trampolines. Compatibility: highest. Risk: the whole native stack inherits async-safety rules.
- **Precedent:** Unix signals; Starnix's emulation on Zircon (ongoing).

## Recommendation

**Recommendation (not a decision): Option B**, with the native ABI defined as follows and the personality mapping below. Option D is deliberately *not* built now and is the first revisit trigger.

**Native ABI.**

1. **Exit record.** Every process object carries, once terminated, `ExitRecord { code: i32, reason: ExitReason, detail: u32 }` with `ExitReason ∈ { Exited, Terminated, Killed, Fault, Limit }`. `Exited` means the process called `exit(code)`. `Terminated` means a request with `Terminate` disposition ended it, or the process called `exit_with_reason(Terminated, detail)`; `detail` carries the request kind and, for the personality, the POSIX signal number. `Killed` is the uncatchable kill. `Fault` carries the fault kind. Anyone holding the process handle with the `wait` right reads the record (CP-06; DM-005: on NT any handle holder can wait on the process object; GR-003: rights are fixed in the handle when it is opened). The process object's `TERMINATED` signal (ADR-0006) is asserted when the record is available.
2. **Request signals and dispositions.** Request kinds: four fixed kinds `Interrupt`, `Terminate`, `Hangup`, `Quit`, plus `Custom(n)` for a small fixed number of custom slots (enough for the POSIX signal numbers the personality maps, `[assumption]` 32). Each process has a disposition per kind and per custom slot: `Terminate` (default), `Ignore`, or `Deliver`. `process_signal(process, kind, detail)` needs the `signal` right on the process handle. Effect: disposition `Terminate` ends the process with `ExitRecord { reason: Terminated, detail }`, running no user code; `Ignore` does nothing; `Deliver` asserts the `REQUEST_PENDING` signal on the process object and queues `(kind, detail)` for the process to read with `process_take_request()`. A process changes its own dispositions with `process_set_disposition(kind, disposition)`. Changing to `Terminate` while a request is queued ends the process at once.
3. **Job-wide delivery.** `job_signal(job, kind, detail)` applies `process_signal` to every process in the job tree. The kernel guarantees that a process created in that tree concurrently with the call either receives the request or is created after it completes (DM-100's `cgroup.kill` lesson). `job_kill(job)` is the uncatchable tree kill. `job_suspend` / `job_resume` stop and continue every thread in the tree, for job control (CP-07, X-12).
4. **Grace.** The kernel enforces no deadline. The requester (a shell, a supervisor, the terminal service) is expected to wait on the job's `TERMINATED` signal with a deadline and then `job_kill`. The data's cleanup takes about 2 ms under strace (`task-02b/event-timelines.md#w9a-…`); the deadline is policy.
5. **Faults.** A thread that faults is suspended. If the process or any ancestor job has an exception channel bound, the fault is delivered as a message on the innermost one; the handler may read and write the thread's state and resume it, or let the process end with `ExitRecord { reason: Fault }`. With no channel bound, the process ends with reason `Fault`. No user code runs on the faulting thread's stack.
6. **Inherited attribute block** (ADR-0003 rule 1). `spawn` takes `{ dispositions: [Disposition; kinds] }`; `snapshot_process` copies the caller's. Nothing else about requests is inherited.
7. **Broken pipes and closed peers** are return values (CP-12): a write to a byte stream whose peer is closed fails with `PeerClosed`. There is no native `SIGPIPE` (DM-077).
8. **Terminal interrupt.** The terminal service (CP-25) holds the *foreground job handle* given to it by the session's shell or broker. On the interrupt character it calls `job_signal(fg_job, Interrupt, 0)`; on hangup, `job_signal(session_job, Hangup, 0)`; on the suspend character, `job_suspend(fg_job)` and a notification to the shell. The terminal never names processes.

**Personality mapping (`libposix` + broker).**

- **SIGCHLD.** No kernel involvement. `libposix` keeps each child's process handle and, for the duration of each wait call (ADR-0006's `pselect`/`sigsuspend`/`nanosleep` implementation), subscribes the children to its port *only if a SIGCHLD handler is installed and unblocked*, because POSIX ignores SIGCHLD by default and an ignored or blocked signal must not interrupt a wait. A child's `TERMINATED` packet, observed at a wait point (`sigsuspend`, `pselect`, `wait*`, `nanosleep`, `pause`, blocking reads on the terminal), runs the handler on the calling thread and then applies the POSIX rule: `EINTR` if the handler ran and the call is non-restarting, else resume the wait. `SA_RESTART` is honoured by resuming.
- **SIGINT, SIGTERM, SIGHUP, SIGQUIT.** `libposix` maps them to request kinds `Interrupt`, `Terminate`, `Hangup`, `Quit`. `sigaction(SIG_DFL)` sets kernel disposition `Terminate`; `SIG_IGN` sets `Ignore`; a handler sets `Deliver`. A delivered request is taken at a wait point or at `libposix` entry and runs the handler on the calling thread. `sigprocmask` blocking a signal defers taking it (the kernel queue holds it). Other POSIX signals (SIGUSR1/2, SIGXCPU, SIGXFSZ, SIGALRM, SIGWINCH, …) map to `Custom(n)` with `n` the signal number, so that `kill -USR1` round-trips. At startup `libposix` initialises every custom slot's kernel disposition from the POSIX default action: `Terminate` for signals whose default is to terminate (SIGUSR1/2, SIGALRM, SIGXCPU, SIGXFSZ), `Ignore` for those whose default is to ignore (SIGWINCH, SIGURG, SIGCHLD's slot), so that an unhandled custom request behaves as POSIX says without `libposix` running.
- **`kill(pid, sig)`.** `libposix` → broker → `process_signal(handle, kind(sig), sig)`. `kill(-pgid, sig)` → `job_signal(group job, …)` (process groups are jobs; the alternative of broker-held sets with user-space fan-out is this ADR's second revisit trigger). `kill(getpid(), sig)` with disposition default → `exit_with_reason(Terminated, sig)`, which is what make's re-raise becomes.
- **Death by signal.** `WIFSIGNALED` ⇔ `reason ∈ { Terminated, Killed, Fault, Limit }`; `WTERMSIG` = `detail` if nonzero else a fixed map (`Interrupt → SIGINT`, `Terminate → SIGTERM`, `Hangup → SIGHUP`, `Killed → SIGKILL`, `Fault(Segv) → SIGSEGV`, …). `WEXITSTATUS` = `code` when `reason = Exited`. This is the "terminated by signal N" that make → make → dash uses (driver 4), and a native shell reads `reason` directly.
- **SIGPIPE.** `PeerClosed` on write: disposition default → `exit_with_reason(Terminated, SIGPIPE)`; ignored or handled → `EPIPE` (plus handler at the next take point). W10's `yes | head` ends as measured.
- **Job control (T0 only).** Process groups are sub-jobs. The broker creates every process it spawns directly (including interactive shells) in a sub-job of its own, and a job-control shell's children are spawned into fresh sub-jobs at `setpgid` time, which the shell calls at spawn (ADR-0003 rule 2's suspended start lets the parent do this before the child runs). `setpgid(0, 0)` or `setpgid(0, getpid())` by a process that is the only member of its job, which is what dash's `setjobctl` does when it enables job control (`task-02/callsite-analysis.md#feature-4-tty-and-job-control`), succeeds by declaring that job a process group. Any `setpgid` that would move a process out of a job it shares with others is refused (CP-07). `tcsetpgrp` hands the foreground job handle to the terminal service through the broker. Ctrl-Z → `job_suspend` + shell notification → `waitpid(WUNTRACED)` reports stopped; `fg`/`bg` → `job_resume`. SIGTTIN: a background job's read on the terminal returns `NotForeground`; `libposix` asks the broker to suspend its job and notify the shell. None of this beyond Ctrl-C and background jobs was exercised (W5), so it is specified to POSIX, not to data.
- **Inherited ignores.** `SIG_IGN` on entry is the kernel disposition `Ignore` inherited through the attribute block; `libposix` reports it to `sigaction` queries, which is what make's `FATAL_SIG` and pdpmake's `init_signal` need (`task-02b/callsite-analysis.md#3-…`).
- **Faults for POSIX programs.** Not emulated in the first release: no T0–T2 workload needed a fault handler (driver 8). `tcc -run` and the T3 crash reporters are `restructure` or out of scope (ADR-0005). A POSIX process that faults ends with reason `Fault`, reported as `WTERMSIG(SIGSEGV)` etc.

**Why B.** It is the only option that is both consistent with CP-10 and sufficient for every measured event (drivers 1–7). Option A is the catalogue. Option C adds a thread per process without helping the programs that exist. Option D is the right answer only if the wait-point rule fails on a real program; the data has no such program, so the primitive should not be in the ABI before it is needed (X-10: an exposed primitive is permanent).

**Principles this recommendation strains.** CP-10 is kept for threads but the kernel holds a disposition table and a request queue per process, which is signal-shaped state. It is justified by driver 5 (default actions without cooperation) and kept to four kinds, a fixed number of custom slots and three dispositions. CP-07's inescapability (X-12) is strained by process groups as sub-jobs: a POSIX `setpgid` that would move a process between shared jobs is refused by the broker. The data shows two uses of `setpgid`: at creation (dash's `forkparent`/`forkchild`) and by the interactive shell on itself in `setjobctl` (`task-02/callsite-analysis.md#feature-4-tty-and-job-control`); both are satisfied by the rule above.

## Consequences

- **Positive.** No async-signal-safety rules anywhere in the native stack. Child exit, interrupt and termination are ordinary port events, so make's 27 restructure sites (about 45 lines, mostly masking) disappear in a native port (M7 estimate). Group delivery closes the forwarding window the data found. Exit reasons are typed.
- **Negative.** A `Deliver`-disposition POSIX program only reacts at wait points or library entry; a compute-bound handler-installing program reacts late (unmeasured; revisit trigger). Kernel keeps a small per-process disposition table. Job control needs sub-jobs created at spawn, which constrains `setpgid`. Fault handlers for POSIX programs are not emulated at first.
- **Follow-up work.** The `abi` types `ExitRecord`, `RequestKind`, `Disposition`, `AttributeBlock`. The terminal service's foreground-job protocol (CP-25). A patch of GNU make's `fatal_error_signal` to run from the main wait, as the M7-recommended calibration (`task-02b/conflict-impact.md#open-questions-…`, item 3). A test that reproduces W9a and W9b on the prototype and checks the exit statuses 130/143 and zero partial targets.

## Invariants

- **INV-0004-1.** No native ABI call registers code to run asynchronously on an existing thread. *Check:* a lint over the `abi` crate that the only entry-point-taking call is thread creation.
- **INV-0004-2.** `ExitRecord` has distinct `code`, `reason` and `detail` fields, and `libposix` derives `WIFSIGNALED` from `reason` only. *Check:* `abi` type plus a round-trip test: a child that calls `exit_with_reason(Terminated, 2)` is reported by `waitpid` as `WIFSIGNALED && WTERMSIG == SIGINT`, and a child that calls `exit(130)` is not.
- **INV-0004-3.** `job_signal` reaches every process in the job tree including ones being created concurrently: no process in the tree exists afterwards that neither received the request nor was created after the call returned. *Check:* a stress test in which a spawner thread numbers each spawn from a shared counter, records the counter value before and after another thread's `job_signal` returns, then asserts that every surviving process with a number below the "before" value has the request queued (or terminated with it), repeated for a stated number of iterations (`[assumption]` 10,000).
- **INV-0004-4.** A process whose disposition for a kind is `Terminate` ends with `ExitRecord { reason: Terminated, detail }` and executes no further user instruction after the request. *Check:* a test with a target that increments a shared counter in a loop; the test calls `process_signal`, waits for `TERMINATED`, reads the counter (value V), waits again, re-reads and asserts it is still V, and asserts the exit record.
- **INV-0004-5.** Dispositions are inherited only through the explicit attribute block: a process spawned with a default block has `Terminate` for every kind. *Check:* spawn test reading dispositions back.
- **INV-0004-6.** A faulting thread runs no user code on its own stack after the fault: it is suspended until an exception handler resumes it or the process ends. *Check:* a test whose handler inspects the suspended thread's program counter and stack pointer and asserts they are at the faulting instruction.
- **INV-0004-7.** Writing to a byte stream with a closed peer returns `PeerClosed`; no process state changes. *Check:* unit test.
- **INV-0004-8.** `libposix` does not subscribe child process handles to the port while `SIGCHLD` is ignored (default), so an ignored SIGCHLD never interrupts a wait. *Check:* a `libposix` test: `nanosleep` with a child exiting during it returns normally when no handler is installed and `EINTR` when one is.

## Open questions

- Reaction latency of a compute-bound POSIX program with a handler: measure with a synthetic program on the prototype; the shells check pending state at every builtin, so the practical case is third-party programs.
- Whether make's cleanup runs correctly from the main wait (M7 estimate, 30 lines): patch and rerun W9 (`task-02b/conflict-impact.md#open-questions-…`, item 3).
- Interrupts arriving during `spawn`/`snapshot_process`: unmeasured; define that a request is queued on the new process only if its disposition is `Deliver` at creation (attribute block).
- Ctrl-Z, SIGTTIN/SIGTTOU and SIGWINCH were not exercised (W5 had no Ctrl-Z); a W5 extension is needed before the job-control mapping is trusted.
- Who may bind an exception channel to a `posix` job, and whether a crash reporter for POSIX programs is wanted in T1/T2 at all (ADR-0005).

## Revisit triggers

- A program in the accepted scope (ADR-0005) needs a handler to run while it is computing: build Option D or Option C.
- A measured scenario shows a process group changing after creation in a way the broker cannot satisfy with sub-jobs: process groups become broker-held sets with user-space fan-out.
- `tcc -run` or an in-scope program needs fault capture on the faulting thread: extend rule 5 with a same-process handler thread (Option C shape) or Option D.
- Cleanup grace handled by requesters proves unworkable (orphans after interrupt in tests): add a kernel-enforced deadline to `job_signal`.
