# ADR-0340: ssh: OpenSSH's client only, with no configuration file, the host of the line as the only host, and keys in its own directory

- **Status:** accepted
- **Date:** 2026-11-13
- **Depends on:** ADR-0109, ADR-0153, ADR-0156, ADR-0172, ADR-0224, ADR-0225, ADR-0228, ADR-0230, ADR-0310, ADR-0312, ADR-0331, ADR-0333, ADR-0337, ADR-0338, ADR-0341, ADR-0342
- **Evidence:** CP-01, CP-27, CP-28, DM-010, DM-087, alternatives-postmortem.md#plan-9--inferno, network/survey.md#plan-9s-tls-filters-and-key-agent, stage-10/survey.md#files-the-ssh-client-touches-unasked, stage-10/survey.md#host-keys, stage-10/survey.md#other-small-ssh-implementations, stage-10/survey.md#scp-sftp-and-the-server, stage-10/survey.md#ssh-and-the-terminal, stage-10/survey.md#ssh-configuration-that-runs-programs-or-changes-the-host, stage-10/survey.md#ssh-implementations, stage-10/survey.md#the-network-as-built, stage-10/survey.md#the-ssh-agent, stage-10/survey.md#what-the-ssh-client-needs, stage-10/survey.md#which-programs-need-a-pty

## Context

Stage 10 wants a person to reach another machine from a Zoraya terminal. The usual tool, OpenSSH's `ssh`, reads a
configuration that can replace the host typed on the line, run arbitrary programs, open listening ports and load
libraries; keeps keys and a record of hosts in the home directory; and guards them with Unix modes
(`stage-10/survey.md#ssh-configuration-that-runs-programs-or-changes-the-host`,
`stage-10/survey.md#files-the-ssh-client-touches-unasked`). Zoraya gives a program the host its line names
(ADR-0224) and has no listening sockets, no pseudo-terminals and one identity. This ADR decides which ssh, client
or also server, where keys and known hosts live, how `+net HOST:22` and the description fit, and what a person
sees when a host's key changes.

**What is known.**

- OpenSSH is under BSD-style licences with no GPL code; libcrypto is optional and its absence "severely restricts"
  the algorithms. Dropbear is MIT-style, small (110 kB static in its own minimal build), bundles its own
  cryptography, has no configuration file, one `known_hosts`, and no sftp client
  (`stage-10/survey.md#ssh-implementations`). Other permissive pieces are libraries or servers
  (`stage-10/survey.md#other-small-ssh-implementations`).
- OpenSSH's client exits when there is no user-database entry for its uid, ignores a private key others could
  read, and uses Unix sockets for the agent and for connection sharing
  (`stage-10/survey.md#what-the-ssh-client-needs`).
- With `HostName`, `Port` or `ProxyJump` in `~/.ssh/config`, `ssh work` contacts whatever the file says;
  `ProxyCommand`, `LocalCommand`, `Match exec` and `KnownHostsCommand` run programs; the forwarding options make
  the client listen (`stage-10/survey.md#ssh-configuration-that-runs-programs-or-changes-the-host`).
- Host keys: by default a new key is added after the person confirms, and a changed key is refused with a warning
  that names the offending line (`stage-10/survey.md#host-keys`).
- The agent holds keys and signs on request; holding its socket is holding the use of every loaded key
  (`stage-10/survey.md#the-ssh-agent`). ADR-0228 names an agent as the later path for client keys
  (`network/survey.md#plan-9s-tls-filters-and-key-agent`).
- The client needs no pseudo-terminal: it sets its own terminal raw, sends `TERM` and the size, and sends a
  window-change on `SIGWINCH` (`stage-10/survey.md#ssh-and-the-terminal`,
  `stage-10/survey.md#which-programs-need-a-pty`). A server allocates one per session and needs listening sockets
  and users (`stage-10/survey.md#scp-sftp-and-the-server`).
- In Zoraya: `+net HOST:22` works before any described program; the `host` operand kind designates an echo only;
  there is no `listen`; one OpenSSL serves every C program (`stage-10/survey.md#the-network-as-built`).

**What is assumed.** That the hosts people reach accept an Ed25519 or ECDSA key or a password. That typing a
passphrase per connection is acceptable until an agent exists.

## Decision drivers

1. **The host on the line is the host contacted**, so that the grant is true (CP-28, INV-0224-1;
   `stage-10/survey.md#ssh-configuration-that-runs-programs-or-changes-the-host`).
2. **Keys are reachable by ssh and by nothing else**, by construction and not by mode bits (CP-01, DM-010).
3. **A changed host key stops the connection, and no shortcut on the line removes that**
   (`stage-10/survey.md#host-keys`).
4. **One cryptographic library in the image** (ADR-0312).
5. **What people know as `ssh`**: its options, its prompts, its escape character (CP-27).
6. **No configuration language of its own to audit** (DM-087).
7. **Only what stage 10 can test** (ADR-0230: the runner is the far end; nothing reaches a guest listener).

## Considered options

### Option A: OpenSSH as on Unix: its files in the home directory, its configuration, the agent

- **Description:** Port the client whole and give it `~/.ssh` and `/etc/ssh`.
- **Evidence for:** Every documented feature: aliases, jump hosts, forwarding, connection sharing, the agent.
- **Evidence against:** Driver 1 fails at once: the configuration chooses the host and can run programs, so no
  grant derived from the line means anything. The agent and sharing need Unix sockets; forwarding needs `listen`
  (`stage-10/survey.md#the-network-as-built`).
- **Cost:** *(estimate)* The port plus sockets and listeners that do not exist.
- **Precedent:** Every Unix.

### Option B: OpenSSH's client, confined: options from the line only, the line's host only, its own directory

- **Description:** The client reads no configuration file. Its description offers the options that cannot change
  the destination or run a program. Keys and `known_hosts` live in ADR-0341's directory.
- **Evidence for:** Drivers 1 to 7. It is the reference implementation, uses the image's OpenSSL, and behaves
  as documented in everything it keeps. The ports of curl and wget were confined the same way (ADR-0310 item 6).
- **Evidence against:** No aliases, jump hosts, forwarding, sharing or agent. Patches to keep out of the
  configuration reader's way. It needs a user-database entry, which the toolchain set supplies with a made-up
  name.
- **Cost:** *(estimate)* A configure-based port with patches for: no configuration file, the user name, the
  askpass variables; an operand rule in the description format.
- **Precedent:** The same client everywhere; `got` runs it by one fixed path and nothing else.

### Option C: Dropbear's client

- **Description:** Port `dbclient` and `dropbearkey`.
- **Evidence for:** Drivers 1 and 6 with less patching: it has no configuration file and reads `HOME` before the
  user database, so it needs neither the configuration patch nor a user-database entry. Small. MIT-style
  (`stage-10/survey.md#ssh-implementations`).
- **Evidence against:** Driver 4: its own bundled cryptography becomes a second library in the image. Driver 5:
  its options and key format differ and it has no sftp client. Its `-o` takes `ProxyCommand` and its `-J` a
  command, and `-y` given twice turns the host-key check off (once, it accepts an unknown key and still aborts
  on a changed one), so its description needs the same refusals as OpenSSH's.
- **Cost:** *(estimate)* A smaller port with fewer patches (none for configuration or the user name); a second
  cryptographic code base to track; a key format to convert.
- **Precedent:** Embedded Linux, mostly as a server.

### Option D: No ssh program: a native remote terminal with a key agent (Plan 9's way)

- **Description:** A native client over a Rust SSH library, with keys in an agent service that signs and never
  reveals, as Plan 9's factotum does.
- **Evidence for:** Driver 2 at its strongest; no files, no configuration, handles throughout
  (`network/survey.md#plan-9s-tls-filters-and-key-agent`; Plan 9 wrote its own,
  `alternatives-postmortem.md#plan-9--inferno`).
- **Evidence against:** Driver 5 and CP-27: a new client with new behaviour; the Rust library surveyed is built
  on an asynchronous runtime Zoraya does not have (`stage-10/survey.md#other-small-ssh-implementations`); git,
  scp and sftp expect the program `ssh`.
- **Cost:** *(estimate)* A project of its own.
- **Precedent:** Plan 9.

## Recommendation

**Recommendation (not a decision): Option B, client only.**

1. **The port.** OpenSSH portable, the release current when its implementation part starts, pinned in
   `ports/sources.lock`,
   built against the OpenSSL of ADR-0312 and zlib. Installed: `/bin/ssh` and `/bin/ssh-keygen`. Not built: the
   agent and `ssh-add`, PKCS#11 and security-key providers, connection sharing.
2. **No server in stage 10.** `sshd` needs listening sockets (`+listen` and `netd`'s `listen` are not built), a
   pseudo-terminal per session (ADR-0338), users and privilege separation, and the tests cannot reach a listener
   in the guest (ADR-0230's revisit trigger). It is a later stage's decision.
3. **No configuration file, and no program from the environment.** Neither `/etc/ssh/ssh_config` nor
   `~/.ssh/config` is read, and `-F` and `-o` are not offered. `SSH_ASKPASS` and `SSH_ASKPASS_REQUIRE` are
   compiled out: a line could otherwise set them and have ssh run a program that inherits its keys. What a person
   would put in a `Host` block they put in a shell function, where `help` shows it:
   `fn build { ssh -l ada build.example.org $args }`.
4. **The line's host is the host.** The description declares the destination as a host that is reached over TCP:

   ```
   name     ssh
   usage    ssh [-p PORT] [-l USER] [-tTv] HOST [COMMAND...]
   program  /bin/ssh
   cwd      none
   operand  HOST  host  the machine, as HOST or USER@HOST
   operand  [COMMAND...]  rest  the command for the far side, taken as it is
   reach    HOST tcp 22 -p
   option   -p PORT text  the port, if not 22
   option   -l USER text  the name to log in as
   data     ssh as ~/.ssh
   ```

   `reach OPERAND tcp PORT [OPTION]` is a new description key: a literal `host` operand designates TCP to that
   host on `PORT`, or on the port `OPTION` gives on the line. The rules are ADR-0224 item 2's: automatic for a
   base-system command, a host from a variable only inside a `+net` word, inside a room only inside the room's
   words. Without the key a `host` operand stays what proposed ADR-0330 made it, an echo. `rest` is a
   new operand kind: every word after `HOST` belongs to the far side's command and is not read for options, which
   is where the shell stops reading. OpenSSH itself reads options again after the host, so the shell puts `--` before
   `HOST` when it starts ssh, which ends ssh's option reading; the port is also
   patched to stop at the host, as a second guard. Then
   `ssh -l ada build.example.org ls -l` has one reading, and an `-o`, `-J`, `-F` or `-i` written after the host
   is a word of the far side's command, not an option of ssh. The options that could
   change the destination or run a program (`-J`, `-W`, `-o`, `-F`, `-L`, `-R`, `-D`, `-A`, `-E`, `-S`) are not in
   the description, so the shell refuses them as a usage mistake.
5. **A user name must be given**, with `-l` or as `USER@HOST`. The one identity of the image's user database is
   not a name on any other machine; a line without one is refused by ssh's own message (a one-line patch).
6. **ssh's own files** are ADR-0341's directory, seen by ssh as `~/.ssh`: `known_hosts`, and the keys
   `ssh-keygen` makes there. They have their default names; `-i` is not offered in stage 10. Only `ssh` and `ssh-keygen`
   carry that `data` line to write; `scp` and `sftp`, later, carry it to read. In another room the directory is
   another, empty one.
7. **Host keys.** `StrictHostKeyChecking` is `ask`, compiled in. The first connection to a host shows ssh's
   question with the key's fingerprint; `yes` stores the key in `known_hosts`. A changed key is refused with
   ssh's warning, and nothing on the line overrides it. The person who knows the change is right removes the old
   key (`ssh-keygen -R HOST`) and connects again, which asks as for a new host. Every other
   host-key setting is OpenSSH's own default, `UpdateHostKeys` included: a server that rotates its key announces
   the new one over a connection already authenticated with the old, so that a rotation does not look like an
   attack and teach the person to remove keys by habit.
8. **Keys and passwords.** `ssh-keygen -t ed25519` writes the key pair into ssh's directory. A passphrase or a
   password is asked on the terminal through `/dev/tty` (ADR-0331), each time: there is no agent. The private key
   file is protected by being in a directory that only the ssh programs of that room are given; ssh's check of
   its mode passes because `ssh-keygen` created it with that mode (ADR-0341 item 11).
9. **The terminal.** With a terminal ssh asks the far side for one, sets its own raw, sends `TERM` (ADR-0333) and
   the size, and a window-change at each `SIGWINCH`; `~.` ends a stuck session. With its input from a file or a
   pipe it asks for none.
10. **What it needs first.** ADR-0331 (raw mode, `/dev/tty`, `SIGWINCH`), ADR-0342's names (`poll` and
    `getnameinfo` among them), the refusal report for hosts (ADR-0224 item 5), and a far end for the tests: an
    ssh server the runner starts on the host, with a throwaway configuration and keys, reached like the other
    test servers (ADR-0230 item 3).
11. **`scp` and `sftp`** start `ssh` as a child. They carry ssh's directory to read only (ADR-0341 items 1 and 7),
    so that the file-transfer code can never write `known_hosts` or a key; a host they meet for the first time is
    first reached with `ssh`. Their descriptions need an operand kind for `HOST:PATH`; they are a follow-up of the
    same part, decided with it.

**Examples.**

```
~> ssh-keygen -t ed25519
(ssh-keygen asks for a passphrase twice and prints the key's fingerprint)
~> ls /data/home/ssh
id_ed25519  id_ed25519.pub
~> grants ssh -l ada build.example.org
ssh gets (a POSIX program):
  in, out, err                  the terminal
  keys                          the terminal, while this line is in front
  random                        the random service
  net: build.example.org:22     reach (operand HOST)
  /system/tls                   read (with the network)
  /data/home/ssh                its own files (it sees them as ~/.ssh)
  ...
~> ssh -l ada build.example.org
(ssh shows the host key's fingerprint and asks whether to continue; after `yes` it stores the key)
ada@build:~$ vi notes.txt
ada@build:~$ exit
~> ssh -l ada build.example.org
(ssh's warning that the remote host identification has changed, the fingerprint of the key the host now
 shows, and the line of known_hosts that holds the old one; it ends with status 255 and sends nothing)
~> ssh-keygen -R build.example.org
~> set h other.example.org
~> ssh -l ada $h
zosh: other.example.org: from $h, outside the line's network grants
  hint: if that is meant: +net other.example.org:22 ssh -l ada $h
~> ssh -J jump.example.org -l ada build.example.org
(refused by the shell before anything runs, as a usage mistake in ADR-0155's form: -J is not an option of
 the description)
```

(`...` stands for the four system lines; the texts in parentheses are ssh's own, described and not quoted;
`/system/tls` comes with every connection that reaches a host, ADR-0311 item 4, though ssh does not read it). In a
room made with `room new ops +net build.example.org:22`, the same line works for a host from a variable too, and
the terminal window's frame carries the pill `+net build.example.org:22`. A full-screen program on the far side
draws in the window as a local one does, because the far side reads the same `TERM`.

**Tensions with accepted ADRs.**

- *ADR-0224 item 2* and proposed *ADR-0330*: the `host` kind is an echo-only designation. The `reach` key makes
  a `host` operand a TCP designation for the description that carries it; ADR-0224's bounds apply unchanged, and
  INV-0224-1's list of what makes a network grant gains "a `host` operand with a `reach` line".
- *ADR-0156*: a third new key (`reach`), with `data` (ADR-0341) and `repository` (ADR-0339), and a new operand
  kind, `rest`.
- *ADR-0228 item 5* ("not now: client certificates ... a key agent, also SSH keys later"): keys arrive now, as
  files in a private directory; the agent stays the later path.
- *ADR-0310 item 6*'s rule (no environment and no file decides trust) is followed in ssh's form: no file decides
  the destination.
- *ADR-0230*: one more test server on the host side; its revisit trigger for a server program in scope is not
  met.

### Effect of the vision

For target 2: an agent's ssh in an untrusted room reaches the room's hosts with the room's own keys, of which it
has none unless the person made them there; nothing in a file can send it elsewhere, and nothing lets it listen.
The person's keys are in another directory that no line of that room can name. Target 3: the ordinary way to reach
a server, a build machine or a router. Networking: the first program on a port other than 80 and 443, and the
first whose trust state (`known_hosts`) the person builds up. Threads: none.

## Consequences

- **Positive.** The client people know, on the image's one OpenSSL; the host typed is the host reached; a changed
  key cannot be waved through; keys private per room without relying on modes; full-screen programs work remotely.
- **Negative.** No server. No aliases in a configuration file, no jump hosts, no forwarding, no agent: a
  passphrase per connection. A user name on every line or in a function; default key names only. `scp` and `sftp` come
  after. Files are
  under `/data/home/ssh`, not in the home directory.
- **Follow-up.** The port and its patches; the `reach` key in `zoraya-describe` and the shell; `ssh.cmd`,
  `ssh-keygen.cmd` and their `help`; the test server on the runner's side; `scp` and `sftp`.

## Invariants

- **INV-0340-1.** ssh's network scope is exactly the host its `HOST` operand names, on port 22 or the port its
  `-p` names, or what a `+net` word or the room gives; no file changes it. *Check:* a host test of the planner
  over literal and value operands, `-p`, rooms; an in-QEMU script with a configuration file in ssh's directory
  and in `/etc/ssh` that names another host, asserting the connection goes to the typed one.
- **INV-0340-2.** The description of `ssh` offers no option that names another host, runs a program, listens or
  reads a file outside ssh's directory, and no environment variable makes ssh run a program. *Check:* a lint
  comparing `ssh.cmd`'s options with a deny list (`-J -W -o -F -L -R -D -A -E -S -w -I -i`), in `make check`; an
  in-QEMU script that sets `SSH_ASKPASS` and `SSH_ASKPASS_REQUIRE` on the line and sees the prompt on the
  terminal and no program started; a host test that words after `HOST` are not read as options by the shell, and an
  in-QEMU script that writes
  `-o ProxyCommand=...`, `-o StrictHostKeyChecking=no`, `-J`, `-F` and `-i` after the host and sees each sent to
  the far side as the command, with no program started and the host-key check unchanged.
- **INV-0340-3.** A host whose key differs from the stored one is never authenticated to: ssh ends with a
  failure status before any credential is sent, whatever the line says. *Check:* an in-QEMU script against the
  runner's server restarted with a second host key, with the server's log showing no authentication attempt.
- **INV-0340-4.** No program in the image listens for ssh connections, and `libc.a` exports no `listen` or
  `accept` for it. *Check:* the image's file list has no `sshd`; INV-0005-1's export check.

## Open questions

- An agent for keys and passphrases (ADR-0228's Option D), which would also serve git's tokens.
- Jump hosts: `-J A B` contacts only `A` directly; a description rule could designate the first hop.
- Whether the remote user name should come from a setting instead of every line.
- `scp` and `sftp`'s operand kind for `HOST:PATH`.
- Port forwarding, once `+listen` exists.

## Revisit triggers

- `+listen`, pseudo-terminals and a way to test a guest listener exist: the server.
- A host in everyday use needs an algorithm the build lacks.
- People keep many hosts: aliases as functions prove too clumsy, and a reviewed, shell-readable hosts list is
  wanted.
