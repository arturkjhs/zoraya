# ADR-0339: git: the repository of the current directory, its own directory and the host of a typed URL; remotes are data and need `+net`

- **Status:** proposed
- **Date:** 2026-11-13
- **Depends on:** ADR-0107, ADR-0109, ADR-0153, ADR-0156, ADR-0172, ADR-0224, ADR-0225, ADR-0228, ADR-0310, ADR-0311, ADR-0312, ADR-0331, ADR-0335, ADR-0337, ADR-0341, ADR-0342
- **Evidence:** CP-01, CP-05, CP-27, CP-28, DM-009, GR-008, alternatives-postmortem.md#plan-9--inferno, stage-10/survey.md#files-git-touches-unasked, stage-10/survey.md#git-licence-and-alternatives, stage-10/survey.md#how-git-starts-other-programs, stage-10/survey.md#pattern-c-a-trusted-helper-with-a-fixed-policy, stage-10/survey.md#the-name-devtty, stage-10/survey.md#the-network-as-built, stage-10/survey.md#what-git-needs

## Context

A working day ends in `git commit` and `git push`. git names almost nothing it touches on its command line: it
finds its repository by walking up from the current directory, reads configuration from three places, takes the
address of a remote from the repository's own configuration, and starts an editor, a pager, hooks and a transport
helper (`stage-10/survey.md#files-git-touches-unasked`, `stage-10/survey.md#how-git-starts-other-programs`). A
Zoraya program gets what its line says (ADR-0153). This ADR decides which git is ported and what the line
`git ...` gives it: files, network and credentials, and what `grants` shows.

**What is known.**

- git is GPL-2.0-only. Permissive alternatives: Game of Trees (ISC; its own commands on git's repository format;
  pushes over ssh only; built around `pledge`, `unveil` and helper processes that parse with no authority);
  gitoxide (MIT or Apache-2.0; no push; runs the external `ssh`); libgit2 (a library)
  (`stage-10/survey.md#git-licence-and-alternatives`).
- git builds without Perl, Python, Tcl, gettext, iconv, expat, `mmap`, Unix sockets and `setitimer`; it needs zlib,
  and libcurl for https. 149 commands are built into the one binary; `git-remote-https` is a separate program it
  starts. It locks by creating `FILE.lock` exclusively and renaming, and needs no record locks
  (`stage-10/survey.md#what-git-needs`, `stage-10/survey.md#files-git-touches-unasked`).
- Walking up for `.git` and then running what the found repository's configuration names was a vulnerability
  (CVE-2022-24765); git's fix is an ownership check (`stage-10/survey.md#files-git-touches-unasked`).
- A repository's configuration names programs to run (`core.sshCommand`, hooks, editor, pager) and the remote's
  URL; an https clone may be redirected to another host on its first request
  (`stage-10/survey.md#files-git-touches-unasked`).
- git asks for a password on `/dev/tty` when no helper is set; the `store` helper keeps credentials in a plaintext
  file; the `cache` helper needs a Unix socket (`stage-10/survey.md#the-name-devtty`,
  `stage-10/survey.md#files-git-touches-unasked`).
- In Zoraya a child of a POSIX program has no network connection and no random service, a POSIX program holds at
  most two connections, and the report and hint for a refused host are decided and not built
  (`stage-10/survey.md#the-network-as-built`). A `url` operand of an image description designates its host
  (ADR-0224 item 2); the shell derives a file name from a URL under a strict rule (ADR-0311).
- `got` confines itself to the repository and the work tree, read-write, and starts the editor unconfined
  (`stage-10/survey.md#pattern-c-a-trusted-helper-with-a-fixed-policy`).

**What is assumed.** That https is the transport people need first, and that typing a token at a prompt, or
choosing to store it, is acceptable until a key agent exists (ADR-0228 item 5).

## Decision drivers

1. **It is git**: the commands, the options and the scripts people know (CP-27: port, do not rewrite;
   `stage-10/survey.md#git-licence-and-alternatives`).
2. **The common lines need no grant words**, or people will work in `+w ~` (ADR-0153 driver 2).
3. **git reaches the repository and nothing beside it** (CP-01, CP-05, DM-009; GR-008's warning about programs
   that open paths late).
4. **No data makes a grant**: what a repository's files say cannot give git a host or a path (INV-0153-3,
   INV-0224-1, CP-28).
5. **Credentials belong to git, in one room** (ADR-0341 driver 1).
6. **What is given is shown** by `grants`, in the same words as everything else (ADR-0153 driver 5).

## Considered options

### Option A: git with the person's files (Unix)

- **Description:** git gets the home directory and the network.
- **Evidence for:** Everything in git's documentation works, including ssh transport, submodules anywhere and any
  helper.
- **Evidence against:** DM-009: a hook or a configured command in any cloned repository runs with all of it; this
  is the setting of CVE-2022-24765 (`stage-10/survey.md#files-git-touches-unasked`). Target 2 is precluded.
- **Cost:** *(estimate)* The port alone.
- **Precedent:** Every Unix.

### Option B: git, given only what the line or the room says

- **Description:** No rule for git. The person writes `+w ~/proj git commit`, or works in a room that holds the
  project and its hosts.
- **Evidence for:** ADR-0153 unchanged: rule 2 says a description cannot widen the current directory, and `make`
  is run exactly so (`+w . make`). Rooms exist for this (ADR-0172).
- **Evidence against:** Driver 2: every git line outside a room carries a grant, and from a subdirectory the grant
  must name the repository's root, which the person must work out. The first experience of git is a refusal.
- **Cost:** *(estimate)* The port alone.
- **Precedent:** `make` in Zoraya today; WASI's `--dir`.

### Option C: git, with the repository found and given by the shell

- **Description:** git's description says that its implicit operand is the repository containing the current
  directory. The shell looks for it within what it holds and gives it; a typed URL gives its host; git's own files
  are ADR-0341's directory. Remotes read from the repository give nothing.
- **Evidence for:** Drivers 1 to 6. The shell, not git, does the upward search, inside its own table, which is
  the capability form of git's ownership check. It is the shape of `got`'s self-confinement, decided by the
  launcher instead of trusted to the program (`stage-10/survey.md#pattern-c-a-trusted-helper-with-a-fixed-policy`).
  ADR-0311 already lets the shell derive what a line means from a description key.
- **Evidence against:** It gives write access the line does not spell out, against ADR-0153 rule 2's words. Hooks
  and configured commands of the repository run with the repository's grant. `fetch` and `push` still need a
  `+net`, which surprises people who cloned without one.
- **Cost:** *(estimate)* A description key and 150 lines in the shell's planner, beside the port.
- **Precedent:** `got`'s `unveil` of repository and work tree; nothing in a shell.

### Option D: Game of Trees instead of git

- **Description:** Port `got`, whose design already separates parsing from authority.
- **Evidence for:** ISC licence; helpers with no file-system access; the parent holds the network descriptor
  (`stage-10/survey.md#git-licence-and-alternatives`). Its structure fits handles well.
- **Evidence against:** Driver 1: it is not git; scripts and habits that call `git` do not work, and it pushes
  over ssh only. Its confinement calls (`pledge`, `unveil`) do not exist here and its helpers assume descriptor
  passing over Unix sockets.
- **Cost:** *(estimate)* A port of a different design, and a second tool for people to learn.
- **Precedent:** OpenBSD.

### Option E: A native client (Plan 9's way), or gitoxide

- **Description:** Write, or adapt from gitoxide's crates, a native program that takes the repository as a
  directory handle and the remote as a scoped connection.
- **Evidence for:** Drivers 3 to 6 by construction; permissive; no child processes. Plan 9 wrote its tools new
  (`alternatives-postmortem.md#plan-9--inferno`).
- **Evidence against:** Driver 1 and CP-27: gitoxide has no push and still runs an external `ssh`
  (`stage-10/survey.md#git-licence-and-alternatives`); a new client is years behind git's behaviour.
- **Cost:** *(estimate)* A project of its own.
- **Precedent:** None at git's completeness.

## Recommendation

**Recommendation (not a decision): Option C.**

1. **The port.** git, the release current when part 10f starts, pinned in `ports/sources.lock`; GPL-2.0-only, a
   separate program in the image as `wget` (GPL-3.0-or-later) is. Built with `NO_PERL`, `NO_PYTHON`, `NO_TCLTK`,
   `NO_GETTEXT`, `NO_ICONV`, `NO_EXPAT`, `NO_MMAP`, `NO_UNIX_SOCKETS` and `NO_SETITIMER`, with zlib, the library of
   the pinned curl and the one OpenSSL of ADR-0312. Installed: `/bin/git` and `/bin/git-remote-https`. Not
   installed: the Perl and shell-script commands, `gitk`, the ssh transport.
2. **The repository.** The description carries a new key, `repository`. Before git starts, the shell looks for a
   directory entry named `.git` in the current directory, then in each parent, **inside its own table**, and stops
   at the first it finds or at the edge of what it holds. If it finds one, git receives that directory as a
   `tree` entry with the reason `the repository of the current directory`. `-C DIR` moves the starting point to
   `DIR`. If it finds none, nothing is added. The entry is automatic because git is a base-system command
   (ADR-0153's Decision). git's own search then ends inside the entry.
3. **Operands.** `git init DIR` and the `DIR` of `git clone URL DIR` are `tree` operands that may be created.
   `git clone URL` without `DIR` gets the directory named by ADR-0311's rule from the URL's last segment, with a
   final `.git` cut; a URL that gives no plain name is refused with the hint to write `DIR`. `git init` with no
   operand needs `+w .`, as any command that changes the current directory does.
4. **git's own files** are ADR-0341's: `data git as ~/.config/git`, holding its configuration and, if the person
   turns it on, stored credentials. The image's `/etc/gitconfig` (read-only, in the toolchain set) sets what the
   system needs: no detached garbage collection (there is no `setsid`), no identity guessed from the user
   database (`user.useConfigOnly`), no credential helper. git is built so that it does not look for
   `~/.gitconfig` (ADR-0341 item 8).
5. **The network: a typed URL gives its host; a remote does not.** The `URL` of `git clone` and `git ls-remote`
   is a `url` operand (ADR-0224 item 2): written on the line, it designates that host and port, with
   `/system/tls` to read (ADR-0311 item 4). `git fetch`, `pull` and `push` take their address from the
   repository's configuration, which is data: they get **no** network from it. The person gives it on the line
   (`+net example.org:443 git push`) or holds it in the project's room. A redirect to another host is refused
   by `netd` like any host the line does not give. In both cases the refusal is shown and the grant offered as
   ADR-0224 item 5 and ADR-0337 say.
6. **https only in stage 10.** `ssh://` and `HOST:PATH` addresses are refused by the description (a `url`
   operand is `http` or `https`), with a hint that says so. git over ssh waits for a way to give a started `ssh`
   its own directory (ADR-0341 item 7).
7. **Certificates are the system's.** As for curl (ADR-0310 item 6): `http.sslVerify`, `http.sslCAInfo` and their
   environment variables are compiled out or ignored; the roots are `/system/tls/roots`.
8. **Credentials.** By default git asks for the user name and the password or token on the terminal
   (`/dev/tty`, ADR-0331), every time. `git config --global credential.helper store` keeps them in git's own
   directory, in plain text, where only git in that room reads them. The `cache` helper is not built.
9. **What git starts.** The pager is `less`, the editor `vi` (ADR-0335), each a child with git's table. Hooks and
   any program the repository's configuration names run as children with git's table too: the repository, git's
   own directory, the network the line gave. They can do to the repository what git can, and no more.
10. **What must exist first.** A child's inheritance of its parent's network connection and of the random service
    (ADR-0225 item 9, decided and not built; ADR-0310's open question), for `git-remote-https`; `poll`
    (ADR-0342); the refusal report for hosts (ADR-0224 item 5).

**Examples.**

```
~/proj/src> git status
On branch main
nothing to commit, working tree clean
~/proj/src> grants git commit -m 'fix the length check'
git gets:
  in, out, err         the terminal
  ~/proj/src           read (current directory)
  ~/proj               change anything in (the repository of the current directory)
  /data/home/git       its own files (it sees them as ~/.config/git)
~/proj/src> git commit -m 'fix the length check'
[main 3f2a9c1] fix the length check
~/proj/src> git push
fatal: unable to access 'https://example.org/ada/proj.git/': Could not resolve host: example.org
  hint: git tried to reach example.org:443, which it was not given
  to allow it: +net example.org:443 git push
~/proj/src> +net example.org:443 git push
Username for 'https://example.org': ada
(git then asks for the password and does not show it)
~> grants git clone https://example.org/ada/proj.git work
git gets:
  in, out, err             the terminal
  random                   the random service
  ~                        read (current directory)
  ~                        create work, and change anything in it (operand DIR)
  net: example.org:443     reach (operand URL)
  /system/tls              read (with the network)
  /data/home/git           its own files (it sees them as ~/.config/git)
```

(with the lines every POSIX program has; git's messages are its own and shortened here). In a room made with
`room new proj +w ~/proj +net example.org:443`, `git push` needs no word. On the desktop the terminal's window
carries the room's pills, `+w ~/proj` and `+net example.org:443`, and the refusal of a `push` outside a room shows
on the terminal's status line while git runs.

**Tensions with accepted ADRs.**

- *ADR-0153 rule 2* ("a description ... cannot widen the current directory: authority comes only from what the
  person typed"). The `repository` key widens it, upward, to the repository's root, with every right of a `tree`.
  This is a real exception, and the architect refused a narrower-sounding one for curl (ADR-0311's `cwd read`).
  Its bounds: image descriptions only; only the nearest directory with `.git` inside what the shell already
  holds, so a room bounds it; shown by `grants` with its reason. If the architect declines it, Option B is the
  design and item 2 becomes a hint: `to allow it: +w ~/proj git commit ...`.
- *ADR-0156*: two new keys in all (`repository` here, `data` in ADR-0341).
- *ADR-0224 item 2* is used as written; *INV-0224-1* is kept by item 5: a remote's address never designates.
- *ADR-0311*'s name rule gains a second user and the `.git` suffix cut.
- *ADR-0287 item 3* (a child has no network) is replaced by ADR-0225 item 9 as decided, for the children of the
  line's programs; `POSIX_NET_BUDGET` of two connections counts the parent and its helper together.
- *ADR-0109*: a second GPL program in the image, separate, with its source pinned.

### Effect of the vision

For target 2: an agent's git in an untrusted room has the room's project and the room's hosts, an empty
configuration and no credentials of the person's, and a hostile repository's hooks reach that repository only.
The typed-URL rule and the refusal of remotes as grants are what keep a cloned repository from choosing where
data goes. Target 3: git works from the first line in a repository. Networking: the first program whose helper
process uses the network. Threads: git may use them; nothing here depends on it.

## Consequences

- **Positive.** Real git; local work with no grant words; clone from a typed URL with none; the repository is
  the boundary for git, its hooks and its children; credentials private to git per room; remotes cannot widen
  anything.
- **Negative.** A write grant that the line does not spell out. `fetch` and `push` outside a room need `+net`
  each time. No ssh transport, no Perl or shell-script commands, no credential cache. Hooks can read git's own
  directory, stored credentials included. A second GPL program.
- **Follow-up.** The port and its patches; the `repository` key; `git.cmd` and `help git`; the system
  `gitconfig`; the prerequisites of item 10; a room example in `docs/tour.md`.

## Invariants

- **INV-0339-1.** git started where the shell's table holds an enclosing directory with `.git` receives a `tree`
  entry on the nearest such directory and on no directory above it; started elsewhere it receives none; the
  search never looks outside the shell's table. *Check:* a host test of the planner with nested repositories, a
  repository above a room's edge, a `.git` that is a file, and `-C`.
- **INV-0339-2.** No network rule comes from a repository's content: `git fetch` on a line with no `+net`, in a
  room with none, has no network connection whatever the repository's configuration says. *Check:* a host test
  of the planner, and an in-QEMU script against the runner's server with a remote configured and no grant.
- **INV-0339-3.** In a clone, commit, log and diff of the test repository, git and its children name no path
  outside the repository, git's own directory, the toolchain set and `/tmp`. *Check:* the in-QEMU script reads
  the report count (ADR-0153 rule 11) and expects zero.
- **INV-0339-4.** `git-remote-https` holds a network scope equal to its parent's and no other connection the
  parent lacks. *Check:* an in-QEMU script with a helper that tries a second host and is refused by `netd`.
- **INV-0339-5.** git accepts a server only with a certificate that the system's roots, the clock and the name
  validate, whatever its configuration or environment says. *Check:* the script of INV-0310-4's kind against the
  runner's expired and wrong-name servers with `http.sslVerify=false` set.

## Open questions

- git over ssh: a way for a started `ssh` to have its own directory (ADR-0341's open question), or an ssh
  transport inside git's process.
- Whether a remote's host should be offered more smoothly: for example the shell reading the remote's URL only
  to word the hint before git starts, which makes no grant.
- Submodules and work trees whose `.git` points outside the repository: refused today, shown by the hint.
- Whether hooks should run at all in an untrusted room, or without git's own directory.
- A key agent for tokens (ADR-0228 Option D).

## Revisit triggers

- The architect declines the `repository` key: Option B.
- People type `+net any` for git: the remote question needs a better answer than a word per line.
- git's Rust requirement (announced for git 3.0) arrives before a Rust `std` build of ports exists.
- An agent or ssh transport exists: credentials move out of files.
